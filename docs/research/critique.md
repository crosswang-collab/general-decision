## 1. 矛盾

1. **praise 到底是「認可」還是「慶祝」** — 角色規格 3.2：「⚠️ §7 規則 3 明訂 log『不罵、不誇』。**praise 這個 mood 名稱容易誤導繪師畫成大笑。正確的表演是『認可』不是『慶祝』。**」黑面「嘴角上揚幅度極小（+6），近乎仍是一字」。UI 3.5：「班長 `praise` 靜態 → **跳起 `translateY(-18px)` 帶 squash & stretch**」「他替你高興」；6.1 第 4 拍還加「一句 ≤10 字台詞氣泡 `scale 0→1` 彈出」＋ 40 顆粒子 ＋ 上行三音。兩章對同一格給了相反的表演指示。

2. **punish 的姿態有兩套** — 角色規格 3.2：阿良「前傾 4°」「頭兩側各 2 道怒氣斜線」、黑面「前傾 6°」，只有老郭「**不前傾。抱胸、頭略別開 5°**」。UI 3.6：「班長姿態 … **抱胸、別過頭、等。不放大、不逼近**」（無 level 分支）。主視覺截圖④：「班長的姿態必須是**抱胸、別過頭、等**」。而「前傾 6° + 最大張口 + 怒氣線」正是主視覺章自己標為「惡意截圖測試風險最高的一張」。

3. **顏色全走 `var()` vs 必須含四個字面值（同一張表裡）** — 生產路徑「主線：改寫 `avatarSvg()`」表同時要求「必須含四個字面值 `#C0392B`、`#8C8C8C`、`rotate(-7 60 36)`、`#5DADE2`」與「顏色 **全部走 `var(--...)`**，不要寫死」。已驗證 `tests/unit/avatar.test.tsx:40-43` 是 `toContain` 字面值。兩條同時成立只有 `var(--sash, #C0392B)` 一種寫法，文件沒寫；照字面執行必紅。

4. **值星帶方向** — 角色規格 2.3：「**本規格不下結論**……必須先找一張確實的參考照定死再發包」。主視覺方案甲卻已寫死：「**左上到右下**一道紅色值星帶斜切過去 … 角度 **−38°**」，而 App 圖示是製作順序的第 1 項。

5. **Capacitor 是既定還是待裁決** — UI 8.2 裁決項 3：「**Capacitor 原生殼**（5.1）。不決定，第五節整節白做」。但主視覺 D 節與生產路徑 C 類直接把 `@capacitor/assets`、`LaunchScreen.storyboard`、`assets/splash.png` 當交付路徑寫。實測 `package.json` 沒有任何 `@capacitor/*`、沒有 `ios/` 目錄。

6. **KV 是一張臉還是三張臉（章內矛盾）** — 主視覺「KV 放什麼」：「**一張臉**，眼睛落在畫面上 1/3」「一句話定義：**一位班長的臉** + 一道具體到不像廣告的命令 + 滿版識別色」。同章「方案 1（**建議主方案**）」卻是三聯幅三格三人，且整張沒有命令標語。

7. **臉高 68% 的裁決地位不一致** — 角色規格 4.1：「⚠️ A／C 明確改寫 §14 的 55–65% 契約，**需使用者放行**」；同章 5.1 卻拿「§14 鎖定 … 臉佔 55–65%」當作否決全身圖的第一條理由。而 UI 8.2「需要裁決的三件事」與生產路徑「建議的動作順序」都沒有收錄這一項。

8. **24 master 這個下限被同時套在 96px 與 60px** — 角色規格 4.2：24 master = 96px 上 2.25px =「一條線存在」。主視覺 App 圖示：「放射短芒的線寬必須 ≥ 畫布 2.3%（≈24），否則 **60px** 上會消失」。60px 的係數是 0.0586，24 master 只有 **1.4px**，低於同一份文件自訂的 2px 門檻；圖示的門檻應是 ≥34（3.4%）。

9. **金色沒有唯一值** — 生產路徑驗收：「**金色上絕對不能放白字**（`#FFC42E` 對白只有 1.59:1）」；UI 章只寫 `--gold`／`--gold2` 未給值；`src/avatar.tsx:16` 是 `#D4AF37`；`design/build.mjs` 另有一份 `gold:#D4AF37`。四個來源三個值。

10. **12 張 vs 15 張** — 三章都寫 `soft` 讓資產 12→15，但主視覺 D6 與生產路徑 C 類仍寫「LINE 貼圖 **12 張表情正好一組**」。

## 2. 不可執行

1. **A／B／C 三個方向從未被定義。** 四章出現數十次「〔依方向而定〕」「方向 A 預期會失敗這一關」「方向 C 因 G.I. Joe 引力最強」，但沒有任何一章寫出 A、B、C 各是什麼風格家族、什麼參考、什麼表面處理。補：一張三欄定義表（家族／表面處理／禁止的子方言／預期在哪一關失敗）。
2. **96px LOD 版沒有載入機制。** 角色規格 A2 要交 LOD 版、生產路徑要「輸出兩個 LOD 變體」，但 `AvatarProps` 沒有 lod 參數、`assetUrl` 只有一條路徑、CSS 沒有尺寸斷點。補：`avatarSvg()` 的新簽名、誰在什麼條件下切、第 14 節路徑要不要加 `@96` 變體。另外 A2 寫「阻塞誰：名牌位、**tab icon**、通知」——這個 app 沒有 tab bar，首頁頭像改成 7rem ≈ 112px，真正的 96px 使用情境要重新指名。
3. **`.meme.stop` 這個 class 不存在。** `MemeTone = 'olive' | 'red' | 'ok'`（`src/meme.tsx:6`），stop 走 `tone="red"`。UI 4.2 的 `.meme.stop::after{…}` 永遠不會命中。補：新增 tone 值或額外 class，並註明 `avatar.test.tsx:78` 只驗 `className` 含 `red`，加了不會紅。
4. **倒數脈動沒有重播機制。** `.meme.red .num{animation:tick 120ms}` 是靜態宣告，數字換值不會重跑。補：`key={n}` 或每拍 class 移除/重加。
5. **「壓迫感來自留白被吃掉的程度」不可交付。** 4.3 給了 88%／96%／104%，但沒說量的是外輪廓包圍盒還是含配件、也沒說 app 內對應什麼（`.face` 是 `width:100%; aspect-ratio:1`，沒有「畫框高度」）。
6. **「惡意截圖測試」沒有判定人與程序。** 黑剪影（48px 並排）與「哪一國的兵」（5/5、≥3/5）都可執行；第 5 關只有「像不像霸凌梗圖」，沒有幾人、誰、什麼算過。
7. **粒子規格缺實作邊界。** 沒說掛在哪個節點（8 節說 `position:fixed` overlay，3.5 沒說）、reduced-motion 下是不出現還是直接在終態。
8. **「紅底換成偏橘的警報紅」沒有值。** 補 hex、dark 版、與白色大字的對比值。
9. **聲音三音沒有可交付格式。** 沒有檔案格式／取樣率／檔名／目錄，也沒說是 Web Audio 合成還是音檔。
10. **「連長室門牌」只有一句話。** 「金框、中文『連長室』、沒有人」——沒有尺寸、沒有落點（`.meme` 只允許三個子節點）、沒說是 `.steps` 內的圖還是偽元素。

## 3. 缺漏（對照前期研究，特別是文化轉譯那份）

1. **「去制服測試」完全消失。** 研究原文：「把制服換成白 T 恤，臉還像不像台灣人？如果不像，代表文化負載全押在制服上，結構太脆——**這是美式改風後最典型的失敗型態**。」四章五個驗收閘門沒有這一關。
2. **「遮字測試」被換義。** 研究的遮字測試是「把所有中文遮掉，還剩多少台灣」；UI 章第九節的「遮字測試」變成「遮掉文字能不能分辨命令／拒絕／罰則／慶祝」。同名不同義，文化版因此沒有任何章節承接。
3. **「先鎖定美式卡通的子方言」沒進文件。** 研究列了六種子方言與安全序，並寫「**超級英雄／G.I. Joe 系（絕對不要碰，那本身就是軍國主義的視覺語彙）**」。四章只在方向 C 段落順帶一句。
4. **軍國主義禁令清單被截短。** 研究清單含「老鷹、月桂葉、飄揚旗幟、握拳、行進剪影、鐵絲網、槍」；角色規格 2.1 禁止欄只留槍／體罰器具／狗牌／迷彩／五角星／聳肩攤手／勾指／敬禮。旗幟、老鷹、月桂、握拳正是 KV 與 App 圖示最容易長出來的東西。
5. **「不撞現有 IP」零驗收項。** 既有簡報盤點 B7 明說這條在新方向下「**重要性還要上調**」（要防 CN／Nickelodeon／Simpsons／Family Guy）。四章完全沒提。
6. **「台灣使用者的卡通識讀是日系的」沒有被回應**，連帶「阿良的藍色汗滴是日式漫符」這件事沒被記錄——角色規格把汗滴當專屬配件並規定 ≥64，卻沒說它在美式化方向下要不要換。
7. **色彩 token 的最終處置沒有任何一章回答。** 既有簡報盤點列為**第 1 優先裁決點**（「C1『可調不可換族』是否推翻？……所有下游都卡在這裡」），並指出「UI token 同時是角色身上的顏色，動一邊不動另一邊 = 班長浮在不同色系的畫面上」。四章沒有色票表、沒答草綠要不要提飽和、沒答四色是整組還是逐色處理。
8. **「工具 vs 娛樂比重」（A3）** 沒被列入任何裁決清單。
9. **`design/build.mjs` 的六個火力變數**（`cmd / r / bw / w / ls / stripe`）UI 第二節只說「這次是把它們回灌」，但新的 `:root[data-level]` 只定義了 `--depth / --pop-scale / --party-count`，六個舊變數怎麼對應沒寫。
10. **四份手抄色值的同步機制**被三章反覆點名，卻沒有任何一章提出解法（產生器？測試？），只重複「目前無任何同步機制」。

## 4. 事實風險

1. **`.num` 的 clamp 上限寫錯（方向相反）。** UI 3.3 寫「`.num`（`:77`）… clamp 上限 3rem → 改 `8px 8px 0`、**上限 5rem**」。實際 `src/styles.css:77` 是 `font-size:clamp(4rem,6.5rem,7rem)` — 上限是 **7rem**，照建議做等於把全 app 最大的數字**縮小**。（3rem 是 `.big` 的上限，`:72`。）
2. **「38% 欄在 1290 寬下右欄僅約 105px」錯。** 1290 是 @3x 裝置像素；CSS 寬 430px，`main` max-width 440 / padding 18 → 內容約 394px，`.meme` 扣 padding 32 與 gap 8 後 38% ≈ **134–150 CSS px**。這是「38%→42%」裁決的**唯一論據**，送裁決前必須重算。
3. **「LINE 貼圖 12 張正好一組」幾乎確定錯。** LINE Creators Market 的貼圖組數是 8/16/24/32/40，沒有 12。文件標了「尺寸需查」，但「12 張正好一組」被當事實用了三次。
4. **Capacitor 全部是未來式當現在式。** 無 `@capacitor/*`、無 `ios/`。「Capacitor 預設就是 storyboard + Splash image set」「`@capacitor/assets` 由 `assets/icon.png` 生成整套」在這個 repo 都還不成立。
5. **iOS 版本時態過期。** 「iOS 26 / Xcode 26 改用 Icon Composer … 需查證你的 Xcode 版本是否強制」——以今天而言這不再是前瞻條目；「iOS 18+ 變體」同理。應改成「查當期 Xcode 的必填變體」。
6. **空狀態文案宣稱「已存在於 §11」但被改寫。** `DECIDE-DEV-DOC-v1.md:309` 原文是「班長在開會。**30 秒**後再報告。」兩章都寫成「三十秒」。五條都宣稱是既有文案，需逐條對回原文。
7. **「服務率 %」**（生產路徑驗收 C 表）應為「服從率」。
8. **截圖第 3 張的 2.3.3 論證有洞。** 「每一格都是 app 內**點頭像可達**的真實畫面」——`OfficerPlate` 只有 home 傳 `onCycle`（`src/app.tsx:231`），cmd 畫面的角色在 `.face` 裡沒有點擊入口；換 level 要回首頁重下口令，命令卡內容會換。「同一張命令卡、三位班長」在 app 內**不可達**。
9. **「汗滴 ≥64，否則 96px 只剩 3.7px」語意錯。** 3.7px 是直徑 40 的結果；64 對應 6px。照字面讀會誤解。
10. 已自標需查證的項目（截圖尺寸／最少張數、iPad、App Preview 編碼、年齡分級、Marketing Guidelines、繪師報價 NT$3–9 萬、ROC 士官領章形制）——標註正確，保留。

1. **§14 資產介面：`mood` 是成文四值。** 「mood = idle|bark|praise|punish」寫在第 14 節規格區塊內（`DECIDE-DEV-DOC-v1.md:364`）。加 `soft` 不只是型別與測試的工時帳單，是**改寫第 14 節**，應與臉高一起列為對 §14 的兩項修約。
2. **§14 臉佔 55–65%：** 角色規格 4.1 的 A／C 68% 直接違反（已自標需放行），但同章 5.1 又把它當有效約束用來否決全身圖。二選一。
3. **§9 規則 2（`1fr 38%`）：** 提議 42%，已自標需裁決——但論據數字有誤（見 4.2）。
4. **§9 規則 4（步驟卡無梗）：** UI 3.3 改 `▸` 為 `--gold`、加 `0 3px 0` 硬陰影、三行 stagger 進場。章內已自承「有人可以主張加硬陰影就是娛樂化」，但它沒有被列進 8.2 的裁決清單（那裡只有三件事）。
5. **§7 規則 3（log 不罵不誇）：** UI 6.1 第 4 拍「班長跳起 + ≤10 字台詞氣泡」等於在 log 畫面新增角色台詞並做慶祝，與規則 3 及角色規格自己的「認可不是慶祝」衝突。這是四章中唯一實質逼近語氣護欄的提案，卻**沒有被標為裁決項**。
6. **§9 規則 1、6、7、8：** 無違反。規則 6 的「只對 `.num` 做 transform、粒子用 fixed overlay」判斷正確；規則 7 提醒膠囊化後要複驗三鍵同 top，正確。
7. **`avatar.test.tsx:63-70` 的解讀正確**（斜紋做 `.face` 背景、章做 `::after` 都不破契約）。**但四章漏了一條警告**：`MemeCard` 的 `children` 是渲染在 `.txt` **內部**（`src/meme.tsx:35`），不是 `.meme` 的子節點——若有人把徽章或粒子當 `children` 傳，測試不會紅但會直接壓在文字上，違反規則 2 的實質。

## 6. 使用者原始需求是否被完整回答

1. **「app 所有人物」— 已完整回答。** 角色規格 §1 盤點九項、逐一判定並給理由（三位班長做完整、連長改「去處符號」、使用者不給臉、其餘不做）。判斷紮實。唯一殘留：連長室門牌無實作規格（見 2.10）。

4. **「UI 娛樂化而非精緻化」— 回答最完整。** 有判準（回應通道數）、逐行現況對照（含行號）、token 組、動態表、觸覺表、獎勵分拍、八條規則相容性檢查、實作順序。扣掉第 2、4 節指出的幾個錯誤後可直接施工。

## 必須補上的三件事

1. **A／B／C 方向定義表（放在角色規格最前面，一頁）。** 每個方向要有：風格家族名與參考作品、表面處理（做舊層／塑膠層／無）、**禁止的子方言**（含研究點名的超級英雄／G.I. Joe 系）、預期通過或失敗哪一道閘門、以及「不得撞現有 IP」的具體對照名單。沒有這張表，全文數十處「〔依方向而定〕」都是空欄，四章無法發包。

2. **一張全案色票表，同時覆蓋 UI token 與角色 SVG。** 必須回答既有簡報盤點的第一裁決點（「可調不可換族」是否推翻、整組還是逐色分級），並給出：`--gold`／`--gold2` 的值、偏橘警報紅的值、三階膚色的新值（現行 ΔL\* 只差 9–10，已被自己判定不合格卻沒給替代）、每個值在淺／深／高對比三態的定義、與白字的對比值，以及「顏色如何同時走 `var()` 又保住 `avatar.test.tsx` 的四個字面值」的寫法規定（`var(--sash, #C0392B)` 這類）。

3. **把散在三章的裁決項合併成一張清單並補齊遺漏。** 目前 UI 8.2 只列三件（42%、`soft`、Capacitor），實際還缺：臉高 68% 改寫 §14、`soft` 改寫 §14 的 mood 四值、步驟卡造型、**praise 是「認可」還是「慶祝」**、**punish 三人是否統一改成抱胸別過頭**、值星帶方向。每項標明違反哪一條成文規則、不放行的備案、誰來答。同時把「**去制服測試**」與文化版「**遮字測試**」加回驗收閘門——目前五關全是形式測試，文化檢測只剩「哪一國的兵」一關撐著。
