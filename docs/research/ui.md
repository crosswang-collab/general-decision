## 一、娛樂化 vs 精緻化，在這個 app 的具體意思

**判準只有一條：一個使用者動作，系統回應幾個通道。**

精緻化 = 一個動作回應一個通道，300ms 內結束（畫面淡入、顏色變一階、完）。
娛樂化 = 一個動作回應三到五個通道（位移 + 過衝 + 顏色 + 觸覺 + 聲音 + 角色表情），而且回應**有去處**（會累積、會被記住）。

所以這一章不是「把顏色調亮」，是把 `styles.css` 現在「只回應一次」的地方改成「回應三次」。

### 1.2 三條刻意**不**娛樂化的（這是設計，不是遺漏）

1. **`.steps` 白卡的內容**：`▸` 三行、無梗、無罵、字重 600。它的「無聊」在娛樂化之後變成刻意的對比——**毒在上面那張卡，情報在下面這張**。這也是這個 app 不是廢話產生器的唯一證據。
2. **`--khaki` 卡其底**：三個彩色都要提飽和，更需要一個安靜的底。而且它是全專案唯二被硬驗的色值（`tests/e2e/system.spec.ts:8` dark `rgb(23,24,19)`、`:15` light `rgb(227,223,208)`），動它就要動測試。
3. **班長的攻擊性一律由文字承擔**：罰則畫面的班長是抱胸、別過頭、等，不放大、不逼近、不指向使用者。壓迫感來自時鐘，不來自身體。這是產品的道德位置，不是美術偏好。

## 二、先建一組變數，不然七個畫面會各做各的

現況：`src/styles.css:4-8` 只有 10 個顏色 token，**沒有任何間距／圓角／字級／陰影／動態 token**。七個畫面各自硬寫時長與圓角，改到第三個畫面就會散。

```css
:root{
  /* 動態 */
  --t-tap:   120ms;  /* 按下／放開 */
  --t-ui:    220ms;  /* 元件狀態變化 */
  --t-screen:300ms;  /* 換畫面 */
  --t-party: 900ms;  /* 慶祝演出 */
  --e-pop: cubic-bezier(.34,1.56,.64,1); /* 過衝，娛樂化主曲線 */
  --e-out: cubic-bezier(.2,.8,.3,1);     /* 無過衝，可讀性優先處用 */
  --e-in:  cubic-bezier(.5,0,.9,.4);     /* 退場 */

  /* 造型 */
  --depth: 4px;    /* 元件厚度，由 level 覆寫 */
  --edge:  2px;    /* 卡通描邊，取代 1px --line */
  --r-box: 18px;   /* 容器圓角 */
  --r-pill:999px;  /* 互動元件 */
}

/* 三段火力：把 level 寫進 DOM（src/app.tsx 根節點加 data-level={level}） */
:root[data-level="0"]{ --depth:3px; --pop-scale:1.03; --party-count:18; }
:root[data-level="1"]{ --depth:4px; --pop-scale:1.07; --party-count:28; }
:root[data-level="2"]{ --depth:6px; --pop-scale:1.12; --party-count:40; }

@media (prefers-reduced-motion: reduce){
  :root{ --t-tap:1ms; --t-ui:1ms; --t-screen:1ms; --t-party:1ms;
         --e-pop:linear; --e-out:linear; --e-in:linear; --pop-scale:1; }
}
@media (prefers-contrast: more){
  :root{ --depth:0px; --edge:3px; }  /* 厚度歸零、描邊加粗，靠形狀不靠陰影 */
}
```

**為什麼這一步必須先做**：`src/app.tsx` 目前的 `level` 只餵給 `officers.ts` 取資料，**沒有寫進 DOM**。加上 `data-level` 之後，「換班長」才會從「換一張臉」升級成「整個 app 提高一階音量」——那是全螢幕面積的變化，比任何頭像差異都更早被感知，而成本只有一個 CSS transition。

`design/build.mjs:16/23/30` 已經有 `cmd / r / bw / w / ls / stripe` 六個火力變數的概念，但它們只活在設計檔裡。這次是把它們回灌到 `src/styles.css`。

| 徽章 | 無 → **一枚徽章 `scale .6→1.06→1`，最後飛進日記頁入口** | **沒有去處的慶祝是煙火，有去處的才是玩具。** 這是這一格唯一不可省略的設計 |
| 班長 | `praise` 靜態 → **跳起 `translateY(-18px)` 帶 squash & stretch（`scaleY .88 / scaleX 1.12`，120ms 內回正）** | 他替你高興，而不是「顯示了一個開心的表情」 |
| 金色放射線 | SVG 內已有四道 | **硬規則：短線、只在兩側、成對、≤ 4 道、絕不成圓、絕不紅白放射。** 卡通化的本能是把它加大加多，一旦擴成頭後全圓光束就是旭日旗 |
| 粒子 | 無 → **`--party-count` 顆（18/28/40，依 level），取 `--gold / --olive / --signal / --white` 四色，放射 120–220px，旋轉 ±180°，重力 +0.3，壽命 600–900ms** | 粒子是娛樂化最直接的「面積 ≥ 40% 且會動」的手段。用 DOM 或 canvas，約 120 行 |

### 3.6 罰則倒數 `stand`（紅卡）

這是整個方案最需要克制的一格。娛樂化在這裡的目標**不是爽，是賭注**。

| 元素 | 現在 → 改成 | 為什麼更好玩 |
|---|---|---|
| `.num` 大數字 | 靜態遞減（`setInterval(..., p.stepMs)`） → **每一拍 `scale(1) → var(--pop-scale) → 1`，120ms `--e-pop`** | 數字自己在喘。倒數如果不動，它只是一個計時器 |
| 卡片壓迫感 | 無 → **四邊往內的暗角（`--ink` 徑向），opacity 隨節拍在 .0 ↔ .18 之間脈動** | **壓迫感來自時鐘，不來自班長。** 這是整個產品的道德位置：他在等你自己做到，不是他在壓你 |
| 節拍來源 | `officers.ts` 的 `stepMs`（1000 / 600 / 500）目前只驅動數字 | **第一次綁到視覺與觸覺**。三段火力的差別終於看得見也摸得到 |
| 班長姿態 | `punish` | **抱胸、別過頭、等。不放大、不逼近、不破框、不指地板、不出現任何體罰器具或暗示。** `punish` 的嘴角必須向下（向上＝獰笑＝施虐） |
| `bot` 那行小字（`p.line`） | 白字直接壓在紅底 | 提飽和後白字對比會貼邊。**小字一律改 `--ink` 或加一條深色底條**，大數字才用白字（≥24px bold 走 AA Large 3:1） |
| 數到 0 | 直接回首頁 | **見第六節 6.2**：蓋一個「登記完畢」章 + `soft` 一幀 200ms + `notification.success` |
| **禁止** | — | **不放 `GAME OVER`、不放 `FAILED`、不放 ✕。** 這個 app 的失敗畫面沒有「失敗」兩個字——他登記你的違紀，他不判你出局 |
| `scale` 的實作限制 | — | **只對 `.num` 做 transform，不要對 `.meme` 做**。`system.spec.ts:71-82` 量的是 `.meme` 的 boundingBox，對它做 scale 雖然等比、比例不變，但沒必要冒這個險 |

### 4.2 可貼上的 CSS

```css
/* 全域互動 */
.btn, .tile, .chip{
  transition: transform var(--t-tap) var(--e-out),
              box-shadow var(--t-tap) var(--e-out),
              background-color var(--t-ui) var(--e-out);
}
.btn{
  min-height: 56px; border-radius: var(--r-pill);
  border: var(--edge) solid var(--ink);
  box-shadow: 0 var(--depth) 0 var(--olive2);
  font-weight: 800;
}
.btn:active, .tile:active{
  transform: translateY(var(--depth)) scale(.97);
  box-shadow: 0 0 0 var(--olive2);
}
.btn:not(:active){ transition-timing-function: var(--e-pop); transition-duration: 180ms; }

/* 換畫面 */
@keyframes in{
  from{ opacity:0; transform: translateY(12px) scale(.96); }
  60% { opacity:1; transform: translateY(-2px) scale(1.02); }
  to  { opacity:1; transform: none; }
}
.screen{ animation: in var(--t-screen) var(--e-pop) both; }

/* 命令卡大字延後一拍 */
@keyframes cap-pop{
  from{ opacity:0; transform: scale(.8); }
  70% { opacity:1; transform: scale(1.04); }
  to  { opacity:1; transform: none; }
}
.meme .cap{ animation: cap-pop 180ms var(--e-pop) 120ms both; }

/* 倒數脈動：只對數字做 transform，不碰 .meme 的 box */
@keyframes tick{ 0%{transform:none} 45%{transform:scale(var(--pop-scale))} 100%{transform:none} }
.meme.red .num{ animation: tick 120ms var(--e-pop); }

/* stop 蓋章：偽元素，不計入 meme.children */
@keyframes stamp{
  from{ opacity:0; transform: rotate(-14deg) scale(1.8); }
  to  { opacity:.9; transform: rotate(-8deg)  scale(1); }
}
.meme.stop::after{ content:""; /* 章的圖形 */ animation: stamp 160ms var(--e-in) both; }

/* 既有的 reduced-motion 分支必須保留：system.spec.ts:63-68 硬驗 animationName === 'none' */
@media (prefers-reduced-motion: reduce){
  .screen{ animation: none; }
  .meme .cap, .meme.red .num, .meme.stop::after{ animation: none; }
}
```

**三條硬規則**

1. `prefers-reduced-motion` 下：所有動畫關閉，**但終態必須直接呈現**（count-up 直接顯示終值、徽章直接在位、蓋章直接在位）。娛樂化不能讓關動態的人少看到資訊。
2. `prefers-contrast: more` 下：`--depth:0`、`--edge:3px`、關閉所有半透明疊層與條紋。**靠形狀不靠陰影。**
3. iOS Dynamic Type：字級上限提高會提高溢出風險。`overflow-wrap:anywhere`（`:77`，`system.spec.ts:35-36` 硬驗）不得移除，且 `.cap` 的 clamp 上限要實測最大字級下不破版。

## 五、觸覺回饋規格

### 5.1 前置決策（不先答，這一節會白做）

這是 Web/PWA。**`navigator.vibrate` 在 iOS Safari 無效。** 兩條路：

- **上 Capacitor 原生殼**（`@capacitor/haptics`），觸覺才會在 iOS 生效。
- **不上殼**：觸覺只在 Android 生效，iOS 使用者拿到的是「少一個通道的娛樂化」。

順帶一提：這個決定同時是 App Store **4.2 最低功能**條款的保險——單人、無帳號的小工具容易被以「更像網站」挑戰，觸覺回饋是「原生才有」的具體證據。建議上殼。

### 5.2 震動表

娛樂化與精緻化的差別不在「有沒有」，在**震動點的密度**：娛樂化每畫面 3–6 個，精緻化 0–1 個。

| 畫面 | 動作 | iOS 型別 | 備註 |
|---|---|---|---|
| 全站 | `.btn` 主鍵按下 | `impact .medium` | 一次操作最多一記主震 |
| 全站 | `.btn.ghost`（沒做）按下 | `impact .light` | 次要行動用輕的 |
| home | 點頭像換班長 | lv0 `selectionChanged` / lv1 `impact .medium` / lv2 `impact .heavy` | **不看畫面也知道自己轉到哪一格** |
| home | 磁貼按下 | `impact .medium` | |
| intake | 每個 chip 切換 | `selectionChanged` | 每個可切換元件都給 |
| cmd | 命令卡進場落定那一幀 | `impact .rigid` | **對齊動畫關鍵幀，不是對齊按鈕** |
| cmd(stop) | 蓋章落下那一幀 | `impact .heavy` | 全 app 唯一的 heavy（除了 lv2 換班長） |
| log | 完成判定 | `notification .success`，**隔 100ms 補一記 `impact .light`** | 雙擊感 = 蓋章感 |
| log | count-up 每 tick | `impact .light`，rate limit 60ms，序列內 light → medium 遞增 | 爬升感 |
| stand | 倒數每一拍 | `impact .light`，序列後 1/3 升到 `.medium` | 綁 `stepMs`，三段火力的節拍差異第一次被摸到 |
| stand | 數到 0 | `notification .success` | **不是 `.error`**。他登記完了，不是你失敗了 |
| 全站 | 錯誤／被擋下（六條錯誤路徑） | `notification .error` | |
| weekly | 三條 bar 各自長滿 | `selectionChanged` ×3 | |

**上限**：一次使用者操作最多 1 記主震；慶祝序列最多 3 記。超過就變成手機在抖，不是回饋。

## 六、獎勵時刻

### 6.1 完成一道口令（`log`）— 四拍，總長 900ms

| 拍 | 時間 | 畫面 | 觸覺 | 聲音 |
|---|---|---|---|---|
| 1 | 0–120ms | 按鈕塌陷 `scale(.96)`、厚度歸零 | `impact .medium` | — |
| 2 | 120–400ms | 卡片切到 `ok` 綠卡；徽章 `scale .6→1.06→1`；`--party-count` 顆粒子從中心放射 120–220px（旋轉 ±180°、重力 +0.3、壽命 600–900ms） | `notification .success` → +100ms `impact .light` | 上行三音（根音→大三度→純五度），320ms |
| 3 | 300–700ms | 登記數 count-up 500ms，數字同步 `scale 1→1.25→1` | 每 tick `impact .light`（rate limit 60ms，強度遞增） | 每 tick 半音上行，最多 8 階 |
| 4 | 500–1000ms | 班長跳起 `translateY(-18px)` + squash & stretch；一句 ≤10 字台詞氣泡 `scale 0→1` 彈出 | — | — |
| **收尾** | 900–1200ms | **徽章飛進日記頁入口並縮小消失** | — | — |

**最後一拍是最重要的。** 沒有去處的慶祝是煙火，有去處的才是玩具。下次打開日記，那一筆會閃一下（3.8）——獎勵被兌現兩次。

**不要做的**：慶祝畫面不可阻擋操作超過 400ms（第 400ms 起任何點擊都應可略過）；粒子不得用放射狀光束構圖。

### 6.2 罰則數到 0（`stand`）

這一格的獎勵**必須是低調的**，因為使用者剛做完 20 下伏地挺身，不是剛贏了一局。

| 拍 | 時間 | 畫面 | 觸覺 | 聲音 |
|---|---|---|---|---|
| 1 | 0–160ms | 數字定在 0，暗角脈動**停止**（不是淡出，是停住——時鐘不跑了） | `notification .success` | 一記下行二音，160ms |
| 2 | 160–360ms | 「登記完畢」章蓋下（同 stop 的蓋章曲線，但 `--ink` 不是紅） | `impact .rigid` | — |
| 3 | 360–560ms | **班長切 `soft` 一幀 200ms**：眼神別開、嘴平，或 3/4 側向 | — | — |
| 4 | 560–860ms | 卡片淡出，回首頁 | — | — |

**第 3 拍是整個產品「情義」的唯一載體。** 罵完之後別過頭、不看你、嘴角鬆一下——這是「班長」與「霸凌者」的分界線。

**成本要誠實講**：`soft` 是第五個 mood，會動到 `src/avatar.tsx:5` 的 `Mood` 型別、資產從 12 張變 15 張、`tests/unit/avatar.test.tsx` 的 3×4 渲染測試、以及 `DECIDE-DEV-DOC-v1.md §12 S3` 的「渲染 3×4 表情不拋錯」判定。**我建議做，但它不是順手。**

**絕對不做**：`GAME OVER`、`FAILED`、✕、紅色閃爍、扣分音效。這個 app 的懲罰是登記，不是判決。

### 6.3 週報產出（`weekly`）

總長 1400ms，可點擊略過。這是全 app 唯一值得超過 1 秒的演出，因為它一週只發生一次。

| 拍 | 時間 | 畫面 | 觸覺 | 聲音 |
|---|---|---|---|---|
| 1 | 0–300ms | 卡片進場；班長 `idle` 頭像先到位 | `impact .light` | — |
| 2 | 300–900ms | **服從率 count-up 600ms**，`--gold` + ink 描邊，字級 ≥3rem，終值時 `scale 1→1.2→1` | 每 tick `impact .light`，rate limit 60ms | 半音上行爬升 |
| 3 | 900–1260ms | 三條 HUD bar 依序長出，stagger 120ms | 每條長滿 `selectionChanged` | — |
| 4 | 1260–1400ms | 講評文字從對話框展開；分享鍵 `scale .9→1` 出現 | — | 上行三音（成功音） |

**分享鍵是這一格真正的產出**。週報的功能不是「告訴你這週如何」，是「給你一張可以貼出去的成績單」。頁尾的帽徽 + 短網址不可省。

## 七、聲音：做，但只做三個時機

**要做。** 理由：這是娛樂化的第三個通道，而且它是**唯一一個在 iOS Safari 上也能用的**通道（觸覺不行，聲音行）。如果不上 Capacitor 殼，聲音就是 iOS 使用者能拿到的唯一非視覺回饋。

### 7.1 三個時機

| 時機 | 性質 | 長度 |
|---|---|---|
| **正回饋**（完成口令、週報產出、罰則數到 0 的第 4 拍） | **上行三音**：根音 → 大三度 → 純五度 | 200–400ms |
| **負回饋**（大事不受理的蓋章、六條錯誤路徑、沒做） | **短促下行二音** | ≤ 200ms |
| **累積**（log 的 count-up、週報服從率 count-up、罰則倒數的最後 3 拍） | 每次 +1 **半音往上爬**，最多 8 階後回到起點 | 每 tick ≤ 80ms |

### 7.2 硬規則

- **音色**：木質／合成馬林巴／短包絡。**不用真實錄音採樣**（哨子聲、口令聲、軍號——全部不要）。真實採樣一放就變廉價，而且「班長吼你」的聲音一旦具體化，反而會削弱使用者腦中自己的那個聲音。
- **音量**：預設 −12 到 −18 dBFS。
- **預設關**。設定頁一個開關（這是這個 app 唯一需要的設定項）。首次完成口令時給一次「要不要開聲音」的一行提示，不要做 onboarding。
- **尊重 iOS 靜音開關**（ambient category）、背景不播、鎖屏不播。
- **絕對不配音效的地方**：頁面切換、滾動、鍵盤輸入、chip 選擇、按鈕一般按下。配了立刻變廉價。觸覺負責這些，聲音只負責「一件事完成了」。

### 7.3 一個明確不做的

**不做班長配音。** 三段火力 × 72 句語料 = 216 段錄音，而且一旦有聲音，語料就不能再隨 Claude 產生（這是產品的核心機制）。這是規模上直接不成立的東西，不是取捨。

### 8.1 §9.1 的四條系統設定

| 條款 | 判定 |
|---|---|
| `prefers-color-scheme`（`:9-12` 十個 token 全數重定義 + `index.html:6` 的 `<meta name="color-scheme">`） | 相容。新 token 必須全部補 dark。**提飽和後最危險的是紅在暗底發光**，dark 版要降明度 |
| 全 rem + `@supports (font:-apple-system-body)`（`:14-15`） | 相容。字級改動全用 rem，`--depth` / `--edge` 用 px 是刻意的（描邊與厚度不該隨字級縮放） |
| `prefers-reduced-motion`（`:23`） | **相容且是硬線**。`.screen{animation:none}` 必須保留（`system.spec.ts:63-68` 硬驗 `animationName === 'none'`）。所有新動畫都要進這個分支，且**終態必須直接呈現** |
| `prefers-contrast:more`（`:13`，目前只重定義 `--mute` 與 `--line`） | **需要擴充**。新配色下要重新檢查全部 token 在淺／深／高對比三種情境。高對比下 `--depth:0`、`--edge:3px`、關閉條紋與半透明疊層。<br>**誠實的代價**：三種設定同時開啟的使用者，拿到的是一個沒有動態、不飽和、且因為多了邊框而**比現況更雜**的畫面。目標族群是 30–50 歲、當過兵的台灣男性，開啟 reduced-motion 與加大字級的比例不低。**這一格必須實機看過才能簽收** |

### 驗收（在既有的 `npm run e2e:shots` 七張截圖之外）

1. **遮字測試**：把所有文字遮掉，七個畫面能不能分辨出「哪個是命令、哪個是拒絕、哪個是罰則、哪個是慶祝」。分辨不出來，代表娛樂化只做在文字上。
2. **靜音 + reduced-motion + 高對比三開測試**：畫面是否仍然可用且不比現況醜。這是第 8.1 節唯一需要實機的一關。
3. **惡意截圖測試**：把 `stand` 那一張單獨切出來、拿掉所有 app 脈絡，看它像不像一張霸凌梗圖。像，就退回第 3.6 節重做班長姿態。
4. **回應密度計數**：每個畫面數一次「一個使用者動作觸發幾個通道」。首頁與 cmd 應該 ≥ 3，`steps` 白卡應該 = 1（它是刻意的對照組）。

**一條不要越線的界線**：要動的是**回應密度**，不是主題。這個 app 的趣味來源是「嚴肅的軍事語氣去處理瑣碎小事」的反差——反差要成立，需要一個**還算嚴肅的框**。所以娛樂化做在**動作與回饋**上（會彈、會震、會慶祝、會累積），不做在**內容與語氣**上（命令仍然具體、步驟仍然無聊、罰則仍然不好笑）。把軍用外皮拿掉，笑點就一起沒了。
