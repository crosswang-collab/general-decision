# 方向 A｜《決斷連》美式電視卡通提案

---

## 1. 一句話定位

**三個吼你的卡通班長，畫風先於年代感。**（16 字）

補一句內部用的操作定義：**借美式的節奏與幾何，台灣只留在配件、文字與語料裡。**

---

## 2. 風格家族

**骨架：家族 4（Cartoon Network 90s–00s 現代厚線）。表面處理：家族 9（當代向量吉祥物）。**
明確排除家族 1（橡皮管）、6（當代 Netflix 扁平）、7（indie 手繪）、8（Pixar 立體）。

選它的四個理由，依重要性：

1. **它就是題目本身。** 使用者說「最像美國電視卡通的那一端」，家族 4 是最多人腦中「美國電視卡通」的預設值（Dexter、Johnny Bravo、PPG、Courage）。不需要翻譯。
2. **它是唯一在七個評分維度都沒有短板的家族（加權 79，第二名 68）。** 其他家族都是某項 5 分、某項 1 分。
3. **它的方法論直接解決本案最難的需求。** 「每個角色分配一個不同的基本形，然後推到極端」不是風格偏好，是這個家族的生產規則。三段火力要「一眼看出換了人」，這條規則就是答案。
4. **它剛好也是向量原生度最高的家族（A+）。** 等寬粗描邊 = 一個 `stroke-width` 數字；正圓、圓角方、梯形 = SVG 原語。**美學上最激進的選擇，同時是生產上最便宜的選擇** —— 這在九個家族裡只發生這一次，其他「更誇張」的路（rubber hose 的紙紋、Pixar 的體積）都要付算圖或繪師的錢。

為什麼混家族 9、而不是讓它當骨架：家族 9 在「三人剪影分離容量」只有 2 分，統一圓角與統一比例會讓三個班長變成同一產品線的三個 SKU。所以它只負責**表面**——圓角半徑系統、色彩節制、透明去背、App 圖示安全區、UI 元件的膠囊語言。**骨架是 CN，表面是 Duolingo。**

為什麼排除橡皮管：它的年代感是**美國 1930**，會和軍教片的**台灣 1990** 正面對撞，兩個年代互相消滅。方向 A 已經要放掉一個年代了，不能再引進第二個。

## 3. 角色造型規則

全部以 **1024×1024 master** 為單位。三人共用一張格線，這是「換人 = 換零件」而不是「換圖」的前提。

### 3.1 共用格線（三人絕對一致，不可個別調整）

| 參數 | 值 | 備註 |
|---|---|---|
| 眼線 Y | **500** | 三人鎖死（既有槽位契約） |
| 肩線 Y | **880** | 三人鎖死 |
| 眼距（兩眼中心） | **260** | |
| 臉高（下顎→髮際） | **700** | = 畫布 **68%**。原契約寫 55–65%，方向 A 明確改為 68% 並三人同值 |
| 外輪廓線寬 | **36**（3.5%） | 96px 上 ≈ 3.4 device px |
| 內部結構線寬 | **22**（2.1%） | 眉、嘴、衣領、口袋蓋 |
| 裝飾線寬下限 | **24** | 低於此值者，96px LOD 版**刪除**而非縮小 |
| 描邊端點 | `stroke-linecap/linejoin: round` | 全域 |

### 3.2 頭身比與構圖

- 胸像（bust），**頭身視覺比 1:2.2**（卡通大頭；只露到胸口第二顆扣子）
- 頸寬 **< 頭寬 × 0.5**（明確反美式：頸不得比頭寬，那是 G.I. Joe 化）
- 肩的方是**衣服的方**，不是三角肌的方。禁止畫肌肉分界線。

### 3.3 頭形（家族 4 的核心：一人一個基本形，推到極端）

| | 阿良 lv0 | 黑面 lv1 | 老郭 lv2 |
|---|---|---|---|
| 頭部基本形 | **正圓** D=660 | **圓角方** 660×640，R=100 | **長倒梯** 上寬 640／下寬 440／高 720，R=60 |
| 肩部基本形 | 窄梯形，肩寬 = 頭寬 ×1.4 | **寬倒三角**，肩寬 = 頭寬 ×2.0 | 平肩，肩寬 = 頭寬 ×1.6 |
| 剪影凸起（**必須跨出輪廓 ≥ 48**） | 帽子傾角 **−15°**（原 −7° 在 96px 是 0.6px 位移，等於零）＋ 帽尖上翹＋後腦一撮呆毛凸 70 | 帽體最高最方（帽高 +60）；值星帶把右肩抬高 50，肩線**刻意不對稱** | 帽下白髮左右各外翻 60；哨繩在頸部形成深 60 的 V 形凹口 |

### 3.4 眼睛（家族 4 的最大特徵，也是本案的種族刻板保險）

- **大眼是硬規則。** 眼白直徑 **≥ 140**（阿良 160），瞳孔直徑 **≥ 56**。理由有二：96px 可讀門檻（8px 寬）；以及避開「只有東亞角色是細線眼」的瞇瞇眼檔案。
- 阿良：正圓眼白 D160 + 圓瞳 D64 + 左上高光 D26
- 黑面：橫向膠囊眼白（160×48）+ 實心圓瞳 D56
- 老郭：深色**方框墨鏡**（兩個 180×112 圓角矩形 + 鼻橋 64×24），但**墨鏡下緣不封口**，punish 時眼睛從鏡片上緣瞪出來
- **每個角色至少一個 mood 眼睛完全睜開**（punish 的圓瞪滿足此條，不得刪除）

### 3.5 線條

- **等寬，不用 tapered line。** 這是方向 A 的核心生產決定：變寬線一旦外框化成填充路徑，線寬從此不可調，96px LOD 版就無法加粗補償。用等寬換到的是「一個數字調全圖」。
- 外輪廓 : 內部線 = **36 : 22 ≈ 1.6 : 1**
- 線色不是純黑，是 **`--ink #16180F`**（帶主色相的近黑，卡通描邊的標準做法）
- 全圖任何地方都有線（家族 4 的規則，與家族 5 無線色塊互斥）

### 3.6 用色數與陰影

- **每個角色 ≤ 6 個純色** ＋ 全域金：膚、膚陰影、制服、制服陰影、ink、一個識別色（阿良水藍汗滴／黑面紅值星帶／老郭墨鏡黑）
- **陰影：一階硬邊 cel shadow，固定左上光源（135°）。** 統一公式：陰影色 = 母色 **H +8°、S +10%、L −18%**。三人、十二張、UI 全部套同一條公式，不逐張挑色。
- **禁止**：漸層、模糊陰影、rim light、質感疊加、網點。不是因為好看與否，是因為它們把生產從 A 級掉到 B/C 級。

### 3.7 四表情（家族 4 的做法：眉與嘴扛全部，眼睛形狀固定）

眉／嘴各做成一個可替換群組，頭與眼完全共用。總資產 = **3 頭 + 3 身 + 4 眉 + 4 嘴 + 3 配件組 = 17 件零件**，組出 12 張。

| mood | 眉 | 嘴 | 附加 |
|---|---|---|---|
| idle | 水平 | 一字（阿良微下弧） | 阿良冒汗（汗滴直徑 **≥ 64**，否則 96px 只剩 3.7px 會被讀成髒點） |
| bark | 內端下壓 −3/+3 | 大張口 + 上齒白塊 | 嘴角兩側各 2 道速度線 |
| praise | 外端上揚 −2/−2 | 上揚弧 | 金色放射線：**短線、只在兩側、成對、≤ 4 道、絕不成圓**（見 §8） |
| punish | 極端下壓 −5/+5 | 最大張口 + 下緣紅 | 頭兩側各 2 道怒氣斜線；**嘴角必須向下**（向上＝獰笑＝施虐） |

## 4. 三段火力：整個 app 的氣壓怎麼變

換頭像只是第一層。方向 A 把 level 提升成**全域主題變數**，讓整個畫面的「聲音大小」跟著轉。

### 4.1 機制

`src/app.tsx` 目前的 `level` 只餵給 `officers.ts` 取資料，**沒有寫進 DOM**。方向 A 要求在根節點加 `data-level={level}`，並在 `src/styles.css` 的 `:root[data-level="0|1|2"]` 定義下表。這是新增，不是既有能力。

（註：`design/build.mjs:16/23/30` 已經有 `cmd / r / bw / w / ls / stripe` 六個火力變數，但它們只活在設計檔裡，`src/styles.css` 完全沒有。這次要把它們回灌到 src，兩份調色盤才會第一次真正連上。）

### 4.2 每階的具體數值

| token / 表現 | lv0 阿良 | lv1 黑面（預設） | lv2 老郭 |
|---|---|---|---|
| `--cmd-bg` 命令卡底 | `#6E8A3E` | `#587631` | `#3D5320` |
| `--page-bg` 頁面底 | `#F4E9D0` | `#F0E4C6` | `#E6D8B4` |
| `--depth` 元件厚度 | 3px | 5px | **8px** |
| `--overshoot` 動畫過衝 | 1.03 | 1.07 | **1.12** |
| `--stripe` 卡片斜紋 | 無 | 4px／不透明 6% | 8px／不透明 12% |
| `.cap` 字重／描邊 | 800／無 | 900／2px ink | **900／4px ink + 金色偏移層** |
| 對話框尾巴 | 圓弧泡泡 | 直角泡泡 | **爆炸 burst 邊緣** |
| 完成演出粒子數 | 18 | 28 | **40** |
| 罰則閃爍節拍 | 1000ms | 600ms | 500ms（沿用既有 `stepMs`，第一次綁到視覺） |
| 按鈕按下位移 | 2px | 3px | 4px |

一句話：**從左到右，背景變暗、描邊變粗、厚度變厚、動作過衝變大、字變吵。** 使用者換班長時，不是換一張臉，是整個 app 提高一階音量。這比任何頭像差異都更早被感知——因為它作用在全螢幕面積上。

## 5. 調色盤

| 現有 token | 處置 | 新值（light） | 新值（dark） | 理由 |
|---|---|---|---|---|
| `--khaki` `#E3DFD0` | **調整** | `#F0E4C6` | `#191B14` | 往暖奶油推，脫離公文紙但保留唯一的中性底。三個彩色全部提飽和後，更需要一個安靜的底 |
| `--ink` `#1B1D1A` | **調整** | `#16180F` | `#F2EEDF` | 更黑，撐得住 3.5% 厚描邊 |
| `--olive` `#4A5733` | **調整** | `#587631` | `#6B8C3C` | 提亮 + 提飽和一階。白字對比 **5.12:1**（AA 通過）。不往黃綠推（會變萊姆／食品感），不往藍綠推（會失去軍綠身分） |
| `--olive2` `#39452A` | **調整** | `#3D5320` | `#4E6B2B` | 陰影階，維持與 olive 的明暗關係 |
| `--signal` `#B3261E` | **取代** | `#D93223` | `#E8503C` | `#B3261E` 幾乎就是 Material error red。往橘推、提亮，語意從「系統錯誤」換成「卡通爆炸」。白字對比 **4.82:1**（AA 通過，已貼邊，不可再提亮） |
| 金 `#D4AF37`（目前不是 token） | **調整並升為正式 token** | `--gold: #F5B21A` / `--gold2: #A06A0C` | 同 | 古典做舊金在高飽和環境會顯灰濁。兩段金（亮金 + 深金）是卡通金的標準結構，而既有 `badge core #7A6314` 已經提供了配對位置 |
| — | **新增** | `--pop: #2F7FB5` | `#4EA3D9` | 美式卡通需要一個跨色輪的撞色。**總面積 ≤ 8%**：選中態、阿良的汗、log 卡的登記數字 |
| `--line` | 顏色保留，**用法取代** | 1px `--line` → **2px `--ink`** | 同 | 「細灰線分區」是精緻化語言，換成卡通厚框 |
| `--card` / `--white` / `--mute` / `--memeText` | 保留 | | | |

**與 C1「可調不可換族」的關係，說白：**
卡其、草綠、金是**調整**（幅度不小，但族沒換）。紅是**取代**（同色族，但語意重新定位）。`--pop` 是**新增一個族**。所以方向 A **不完全符合 C1**，需要使用者明確放行到「加飽和 + 一個新撞色」這一格。它沒有走到「整組換掉」。

**會連帶爆掉的東西（必須同步改，不是可選）：**
- `tests/e2e/system.spec.ts:8`（深色 `rgb(23,24,19)`）與 `:15`（淺色 `rgb(227,223,208)`）是**唯二被硬驗的色值**，改 `--khaki` 直接紅燈。
- `index.html:7` 的 `<meta name="theme-color" content="#4A5733">` 是 olive 的手抄本，無 dark 版。
- `public/manifest.webmanifest:9-10` 的 `background_color` / `theme_color` 同樣是手抄本。
- `design/build.mjs:10-11` 的 LIGHT / DARK 是第三份手抄本，沒有任何同步機制。

## 6. UI 怎麼跟著變

### 6.1 home（首頁）

- 班長頭像：`.officer .av` 從 `5.75rem` 方框 → **9rem 圓形 badge**，`border: 3px solid var(--ink)`，硬陰影 `0 5px 0 var(--olive2)`。頭像是首頁最大的單一元素。
- 對話框：`.bubble` 改成真正的卡通對話泡，**尖角指向頭像**（CSS 三角形，不用圖），radius 8px → **20px**，border 1px → **2px ink**，加 `0 4px 0 rgba(22,24,15,.2)`。
- 四磁貼：radius 8px → **18px**，border 1px `--line` → **2px `--ink`**，`box-shadow: 0 var(--depth) 0 var(--olive2)`；`:active` 時 shadow 歸 `0 1px 0` 並 `translateY(var(--depth))`。`.tile b` 的 2rem 數字改 `--gold` + 2px ink 描邊。
- 三小鍵：radius 6px → **999px**（膠囊）。`flex-wrap:nowrap` + `overflow-x:auto` 的小螢幕橫捲行為**完全不動**（`system.spec.ts:46-60` 硬驗）。
- 保留：`.officer` 在畫面頂端（規則 1）、點頭像換班長（唯一入口）。

### 6.2 cmd（命令卡，4:5）

**不動的（測試鎖死，一個字都不碰）**：`aspect-ratio: 4/5`（`system.spec.ts:71-82` 容許 ±0.05）、`.meme` 的三個子節點恰為 `['tag','txt','face']`（`avatar.test.tsx:63-70` 驗 className 陣列完全相等）、`data-testid` 六個、`red`/`ok`/`wide` class 名、`overflow-wrap: anywhere`。

**改的**：
- 卡片底改滿版 `--cmd-bg`，內縮 12px 畫一圈 **3px ink 內框**（漫畫分鏡框）。
- `.cap` 現行的五向 `#000` text-shadow → 換成 **4px ink 描邊 + 6px 硬位移金色陰影**（`text-shadow: 6px 6px 0 var(--gold2)` + `-webkit-text-stroke`）。字重 900。
- `.num` 的 `3px 3px 0 #000` → `8px 8px 0 var(--ink)`，並把 clamp 上限從 3rem 提到 **5rem**。
- **`.face` 必須補 `object-fit: contain`** ——全專案目前一個 `object-fit` 都沒有（grep 無結果），非正方形 raster 會被**拉伸變形**。這是既有 bug，方向 A 順手修。
- 角色允許頭頂被卡片上緣裁掉，但**仍是 grid 兄弟節點、不得 absolute、不得跨進文字欄**（規則 2 不動）。
- **一個誠實的物理問題**：68% 臉高遇上 38% 欄寬，頭要夠大就會擠到文字欄。建議把 `1fr 38%` 調成 `1fr 42%`——這條**零測試覆蓋**（全專案唯一的 `gridTemplateColumns` 斷言只驗週報 wide 解析成 1 欄），改了全綠。但它是規則 2 的明文數字，需要使用者放行。
- 步驟白卡（`.steps`）：radius 8 → 18、border → 2px ink、`▸` 前綴保留。**內容不加任何梗、不加任何裝飾**（規則 4 是產品層，方向 A 不碰）。

### 6.3 stand（罰則倒數，紅卡）

- `.num` 大數字：白字 + **4px ink 描邊 + `--gold` 第二層偏移**，字級上限提到 6rem。
- 每一拍：數字 `scale 1.0 → 1.18 → 1.0`，140ms，`cubic-bezier(.34,1.56,.64,1)`；卡片內框閃一次 2px `--gold`。節拍直接用既有的 `stepMs`（1000/600/500）。
- `prefers-reduced-motion` 下只換數值、不做任何 transform（`system.spec.ts:63-68` 硬驗 `animationName === 'none'`，這條不能破）。
- **班長姿態：別過頭／抱胸／等，不得放大逼近、不得指向讀者、不得笑。** 壓迫感來自時鐘，不來自身體。方向 A 雖然放掉了很多在地元素，**這一條不放** ——它是產品的道德位置，不是美術偏好。

### 6.4 log（登記）— 新增獎勵演出

目前是 0。補一段四拍、總長 900ms：
按鈕塌陷 120ms → 徽章 `scale .6 → 1.06 → 1` → 服從次數 count-up 500ms（數字同步 `scale 1.25` 回彈）→ 班長跳起 + 一句 ≤10 字。粒子取 `--gold / --olive / --signal / --white` 四色，數量依 level 18/28/40。
**關鍵：徽章必須飛進日記頁的某一格。** 沒有去處的慶祝是煙火，有去處的才是玩具。

### 6.5 空狀態（五個，零新資產）

`頭像 + 一句話 + 一顆按鈕`。文案第 11 節已經寫好，直接配既有 mood：日記空＝阿良 idle／週報未到＝黑面 idle／API 掛了＝老郭 idle／附近沒開的＝黑面 bark／定位被拒＝黑面 idle。

## 7. 主視覺

**等距三格並列，同槽位疊影，差異全在氣壓不在姿勢。**

- 畫布 **1080×1350**（4:5，與分享卡同比）。另出 1200×630 OG 橫切、1080×1920 IG Story。
- 三格等寬，格間 **16px ink gutter**（漫畫分鏡框，而不是留白），最外圈 8px ink 外框。
- **背景明度階梯**：左格 `#F4E9D0` → 中格 `#587631` → 右格 `#3D5320`。同一張圖裡由亮走到暗 = 火力上升，一個字不用寫。
- 三人**眼線與肩線完全對齊**（同一條格線，走向量路線這是零成本的結構保證）。表情用 **idle / bark / punish**，讀成「同一個動作被三種人執行」。
- **佔滿度遞增**：比例一致，但阿良留白多、老郭帽子頂到畫框上緣被裁。壓迫感靠留白，不靠放大。
- **紅只出現兩次**：中格的值星帶、右格的哨繩。兩點連成斜向動線，把三格串起來並告訴眼睛往右走。
- 上方 1/4 一個 **burst 形狀**（家族 4 的招牌）放一句 app 內真實語料，不是廣告標語：`阿財魯肉飯。十二分鐘。`
- 底部一條 `--gold` 刻度線，三個 tick，**第 2 個高亮**（對應預設 level 1）。這條刻度是把「合照」翻譯成「選擇器」的關鍵零件，不能省。

**不放**：手機外框、三人以上、功能條列、App Store 徽章、漸層光暈、任何在 200px 寬會消失的細節。

**明確排除的備案**：一人三面／三段曝光疊影。語意最準，但小尺寸必糊，社群縮圖直接失效。

## 8. 這個方向的代價

這一節我不替方向 A 說話。

### 8.1 它犧牲的第一件事：笑點的來源

《決斷連》的趣味是**「嚴肅的軍事語氣去處理瑣碎小事」的反差**。反差的一端是「嚴肅」，而嚴肅的載體是年代感——軍教片、草綠服、油印公文、莒光日。**美式向量卡通是「現在」的，圖面上沒有任何一個元素在說 1990。** 方向 A 把年代感換成畫風辨識度，等於把反差的一端抽掉。

結果不是「變得比較不好笑」，是**笑點性質改變**：從「反差」退化成「角色很吵」。吵是可以做到的，但吵不稀有——市面上每一個 mascot app 都在吵。

### 8.2 它犧牲的第二件事：不可讓渡清單的下半段

文化轉譯研究列了十項不可讓渡，方向 A 明確放掉其中三到五項：

- **草綠服的結構**（純色、寬鬆、燙線、內務感）→ 美式卡通會把制服畫成貼合身體的乾淨色塊。方向 A 接受。
- **三分頭＋帽子曬痕** → 大頭卡通比例下，髮際線與曬痕都在 96px 消失。方向 A 接受。
- **白色硬質名牌＋繁體中文** → 保留，但在 68% 臉高的構圖下，胸口只剩窄窄一條，名牌會被壓到 96px 讀不出字。**這是方向 A 最可惜的一項**，因為它成本最低效益最高。
- **「情義」的表情層** → 見 8.4，這是最嚴重的一項。

**去制服測試會失敗。** 把制服換成白 T 恤，這三張臉不像台灣人。這代表文化負載全押在制服上，結構是脆的——而方向 A 又同時削弱了制服。兩頭都鬆。

### 8.3 具體暴露的風險，逐條對照

| 風險（出自文化轉譯研究） | 方向 A 的暴露程度 | 有沒有解 |
|---|---|---|
| **老郭 = R. Lee Ermey**（墨鏡＋方下顎＋哨子 = 美式 drill sergeant 全套） | **最高。** 我們刻意往美式推，這個引力會被放大。而墨鏡又正好是家族 4 最好用的剪影零件 | 有解但互斥：改老花眼鏡滑鼻尖＋哨子收口袋，在地十倍，但**同時削弱卡通辨識度與既有 §14 規格**。這是方向 A 內部的真實張力，我不假裝能兩全 |
| **五角星帽徽** | **高，而且現行 brief 就是錯的。** 金/紅五角星是解放軍與蘇聯系統的符號，中華民國是青天白日。方向 A 要把帽徽放大成 App 圖示與全站識別，錯誤會被放到最大 | **必改**：做一個虛構部隊徽（取十二道光芒的節奏，明確不是國徽本體）。這一項無論走哪個方向都要改 |
| **旭日旗誤讀**（praise 的金色放射線） | **中高。** 卡通化的本能就是把放射線加大加多，一旦擴成頭後全圓光束就是旭日旗 | 硬規則已寫進 §3.7：短線、只在兩側、成對、≤4 道、絕不成圓、絕不紅白 |
| **霸凌讀感**（punish 脫離脈絡） | **中高。** 高飽和紅 + 拉滿的表情 + 卡通誇張，惡意截圖測試最容易在這一張翻車 | §6.3 的姿態禁令（別過頭/抱胸/不逼近）是唯一防線，必須寫進發包文件而不是驗收時再看 |
| **撞既有 IP** | **高，而且比舊方向高得多。** 家族 4 的角色設計慣例高度收斂，Dexter / Johnny Bravo / PPG 的血統一眼可辨。原 brief 的「不能像日本動漫」在新方向下要換成「不能像 CN / Nickelodeon / 辛普森」，而這個風險的機率上升了 | 靠三人的基本形分配（正圓/圓角方/長倒梯）拉開，但這三個形狀本身也是那些作品用過的。**這一項我沒有乾淨的解** |
| **campaign hat / 迷彩 / high-and-tight 的模型漂移** | **低。** 這是方向 A 唯一比其他方向乾淨的地方——純 SVG 路線沒有生成模型，不會擲骰子 | 結構上不會發生 |
| **瞇瞇眼刻板** | **低。** 家族 4 的大眼反而是保險 | 已寫進硬規則 |

### 8.4 最嚴重的一項：它沒有「藏」的位置

軍教片班長的核心情緒節拍是**刀子嘴豆腐心**——罵完之後別過頭、不看你、嘴角鬆一下。這是這個角色之所以是「班長」而不是「霸凌者」的唯一分界。

而家族 4 的表演訓練是**「每一格都要完全可讀、幅度拉滿」**。它沒有「藏」這個動作。四個 mood 全部是高幅度，一旦再用美式放大，**只剩「兇」**。

補救是加第五個 mood `soft`（罰則結束後用，眼神別開、嘴平、或 3/4 背面）。但這不是零成本：

- `src/avatar.tsx:5` 的 `Mood` 型別要改
- 資產從 12 張變 15 張
- `tests/unit/avatar.test.tsx` 的 3×4 渲染測試要改
- `DECIDE-DEV-DOC-v1.md` §12 S3 的完成判定「渲染 3×4 表情不拋錯」要改
- `src/app.tsx` 要在罰則倒數結束那一幀切 mood

**我建議做，但它是真實的程式與文件成本，不是順手。**

### 8.5 這個方向會在什麼情況下失敗

**失敗情境 A：目標客群不接這個語彙。**
目標是當過兵、記得軍教片的 30–50 歲台灣男性。他們的卡通識讀是**日系的**，不是美系的。現行 SVG 阿良臉上那顆藍色汗滴（`#5DADE2`）是日式漫符，對台灣人的可讀性其實高於任何美式等效物。方向 A 賭的是「畫風本身好看」能跨過陌生感。**這個賭注可能輸，而且輸的方式很安靜**——不是被討厭，是沒感覺。

**失敗情境 B（我認為這是方向 A 最大的邏輯漏洞）：「外國人也覺得好看」這個目標本身有問題。**
這個 app 的全部語料是繁體中文軍教片黑話——「你各位啊」「合理的要求是訓練」「我看過的菜鳥比你吃過的饅頭多」。外國人**看不懂任何一個字**。所以對外國人而言，這個產品的賣點只剩畫風。而只靠畫風競爭，它要面對的是整個美式吉祥物 app 的紅海，**而且我們手上沒有任何差異化資產**——那個差異化資產本來叫「台灣軍教片」，剛好是方向 A 決定放掉的東西。

換句話說：**方向 A 為了取悅一群看不懂它的人，放棄了讓看得懂它的人覺得它獨一無二的東西。** 如果要選這個方向，這個矛盾必須被正面回答（例如：是不是要做英文版？語料能不能翻譯而不死？），不能靠美術解決。

**失敗情境 C：技術面的高飽和陷阱。**
提飽和後，`--signal #D93223` 對白字只剩 4.82:1（已貼邊，不可再提亮）；深色模式下高飽和紅會發光爆邊；紅與新金 `#F5B21A` 的色相距離縮短，在 96px 與小尺寸下可能互相干擾。`prefers-contrast: more` 目前只重定義 `--mute` 與 `--line` 兩個變數，新配色下要重新檢查全部十一個 token 在淺／深／高對比三種情境的表現。**這是加飽和方案的隱藏成本，工作量要重估。**

## 9. 生產可行性

**純 SVG 做得出來。零繪師、零算圖。這是方向 A 最強的一項，而且是它相對其他方向唯一有結構性優勢的地方。**

### 9.1 為什麼成立

家族 4 的全部形狀語彙——正圓、圓角矩形、梯形、膠囊、等寬描邊——是 SVG 原語的完整對應。粗外輪廓用「同一路徑先粗描邊墊底、再填色疊上」兩層就完成。硬邊 cel shadow 是一個剪裁過的填充路徑，不是漸層。整套沒有一項掉出 A 級。

**十二張的一致性從「機率問題」變成「確定性問題」**：它們共用同一條頭部路徑、同一條格線，不是十二次生成。原 brief 驗收表裡最難過的「三人眼線與肩線一致」「配件沒多沒少」，在這條路上不是檢查項目，是結構保證。

### 9.2 建議走哪條介面

**建議 (i)：重寫 `src/avatar.tsx` 的 `avatarSvg()` 回傳字串，不走 `.webp`。**

理由：
- `AvatarProps`、`assetUrl`、`Avatar` 介面零改動。
- `public/officers/` 目前是空的，線上永遠走 SVG 分支——也就是說**今天上線的就是這條路**，不需要等資產。
- 決定性理由：**inline SVG 才能被 CSS 變數觸及。** 現行 avatar 的所有色票都是 SVG 屬性字面值（`#EFC9A6`、`#33402A`、`#1F1F1C`…），沒有 `currentColor` 也沒有 `var()`，後果是**深色模式下頭像完全不變色**，而且 avatar 的 `#1F1F1C` ≠ `--ink`、`#33402A` ≠ `--olive`。方向 A 把它們全部換成 `var(--...)`，順手修掉這個既有 bug，並讓 §4 的 level 主題能真的作用到角色身上。
- `tests/unit/avatar.test.tsx:60` 要求 `.face svg` 存在（梗圖卡上必須是 inline SVG 節點），走 (i) 自然滿足。

**方案 (ii)（交 `.webp` 檔）的代價**：`.webp` 副檔名寫死在 `src/avatar.tsx:8`，png/svg 檔不會被撿到；raster 分支完全忽略 `onDark`，圖檔若烘進底色會直接蓋在卡片上；而且必須先補 `object-fit: contain`，否則非正方形會拉伸變形。**建議只把 raster 當 App 圖示與 KV 的匯出格式，不當 app 內資產。**

### 9.3 兩個 LOD，不是兩套圖

- **1024 完整版**：給 App 圖示（匯出 PNG，不可有 alpha、不可自畫圓角）、KV、分享卡。
- **96 簡化版**：給名牌。同一份 SVG，用 CSS 或第二個變體做三件事——刪除所有 `stroke-width < 24` 的元素（老郭的法令紋、阿良的汗滴邊緣）、外輪廓從 3.5% 加粗到 4%、關閉所有裝飾細節。
- **這件事只有等寬描邊路線做得到。** 變寬線一旦外框化成填充路徑，線寬從此不可調，你再也不能說「把所有線加粗 20% 做 96px 版」。這是 §3.5 拒絕 tapered line 的唯一理由。

### 9.4 動態不需要額外工具

squash & stretch、過衝、眨眼 idle loop，全部用 CSS `transform` 作用在 SVG 群組上就能做。**不需要 Lottie、不需要影格序列、不需要新的資產管線。** 既有的 `prefers-reduced-motion` 分支（`src/styles.css:23`）直接繼承。

### 9.5 什麼情況下這條路會破功

三件事會讓它從 A 級掉到 B/C 級，**任一發生就必須回頭找繪師或算圖**：

1. 有人要求 tapered line（變寬描邊）
2. 有人要求紙紋、網點、做舊質感
3. 有人要求立體皮膚或 rim light（SVG 沒有可用的 mesh gradient，瀏覽器沒實作，只能疊十幾層放射狀漸層近似，改一個角度就全部重來）

方向 A 明確放棄這三者。**這是它「最像美國電視卡通」與「純向量可做」能同時成立的全部原因**——家族 4 剛好不需要它們。

### 9.6 驗收閘門（取代目測）

1. **黑剪影測試**：三人填 100% 黑、去掉所有內部細節、縮到 48px 並排。分不出來就退回重做。這關過了，96px 一定過。
2. **灰階測試**：相鄰色塊 ΔL* ≥ 20。注意膚色三階（#EFC9A6 / #D9A87C / #C98F62）灰階只差 9–10，**不足**——三人的區隔必須靠帽徽金、值星帶紅、墨鏡黑來補，不能靠膚色。
3. **LOD 測試**：隱藏所有 `stroke-width < 24` 的元素，角色是否仍成立。
4. **疊圖測試**：三人 idle 疊在一起降透明度，眼線與肩線必須完全重合。（走向量這關是零成本的。）
5. **惡意截圖測試**：punish 單張切出來、拿掉所有 app 脈絡、配最惡意的一句話。看起來像霸凌梗圖或軍國主義海報就退回。
6. **「哪一國的兵」測試**：5 個當過兵的人看 96px 縮圖、無說明、2 秒內回答。**方向 A 預期會失敗這一關**——這不是 bug，是它的定價。但要在發包前知道自己付了這筆錢。
