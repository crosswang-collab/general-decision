# 決斷連 · UI 美化設計簡報（給 Claude Design）

> 用法：整份貼進 Claude Design 當第一則訊息，附上 `decide-mock-v5.html` 與 `shots/*.png`。
> 這份簡報的目標是「讓現有的 app 長得像 App Store 精選會挑的作品」，不是重新發明產品。
> 產品邏輯、文案規則、七張卡、三位班長都已鎖定，設計只動視覺與互動細節。

---

## 0. 一句話

一個手機 app：使用者按一顆鍵，一位台灣 90 年代軍教片風格的「班長」下一道不可拒絕的命令（吃什麼／去哪／去不去／幾點睡……），使用者回報完成或沒做，完成就登記，沒做就罰則倒數。角色是賣點，命令是產品。

目標感受：**一個有脾氣、但你會想每天打開的工具。** 像 Carrot Weather 那種「毒舌但可靠」，像 Streaks 那種「一鍵就做完」。

---

## 1. 架構前提（設計要知道，但不用處理）

- 技術：React + Vite 的 PWA，之後用 **Capacitor 包成 iOS 原生 app** 上架。
- 這代表：沒有瀏覽器框、有 safe area（瀏海／Home 指示條）、可用系統分享面板、可用觸覺回饋、需要啟動畫面與 1024×1024 App Store 圖示。
- 後端只有兩支 API（下命令／產週報），設計不用管。
- 資料只存手機本機，沒有帳號、沒有登入頁、沒有 onboarding 需要收資料。**不要設計登入／註冊流程。**
- 三位班長目前是程式畫的 SVG 佔位頭像，正式版會換繪師的 512×512 透明背景 webp（4 種表情：idle／bark／praise／punish）。設計時把頭像視為可替換資產，**不要把頭像跟版面焊死**。

---

## 2. 不可更動的規則（產品文件第 9 節，設計不得推翻）

| 規則 | 意思 |
|---|---|
| 班長永遠在最上面 | 首頁／點名／日記的頂部是班長頭像 + 名牌；他是說話者，整個畫面是他的台詞 |
| 梗圖卡兩欄 | 命令卡左欄文字（上／大／下三段）、右欄角色。**角色絕對不能用絕對定位壓在字上**（v4 犯過這個錯） |
| 字級用 clamp | 梗圖文字全部要能自動縮放，超長店名要能換行不溢出 |
| 步驟卡分離 | 執行步驟放在梗圖卡下方的獨立白卡，`▸` 前綴，**不放梗、不放罵** |
| 主按鈕一顆 | 每個畫面只有一顆主要動詞按鈕，放拇指區；「沒做」永遠是 ghost 樣式，不能比主按鈕醒目 |
| 4:5 可截圖 | 命令卡、登記卡、罰則卡是 4:5 比例，因為使用者會截圖分享到 IG／LINE |
| 小螢幕 | 高度 < 700px 時，首頁三顆小鍵改為一列橫向捲動 |
| 跟隨系統 | 深淺色、iOS 動態字級、減少動態、高對比全部要跟系統 |

文案規則也鎖定：罵行為不罵人（只罵猶豫／拖延／菜／屁股重／賴床），命令本體零毒性，登記文字不罵不誇。**設計不需要寫文案**，用 mock 裡的文字即可。

## 3. 現況（附件）

- `decide-mock-v5.html`：使用者已通過的畫面基準。開瀏覽器、切 iPhone 尺寸看。點頭像可換班長，點磁貼可走完整流程。
- `shots/01-home.png` ～ `07-weekly.png`：目前實作的七張截圖。
- 目前風格：卡其底、墨色字、草綠命令卡、紅色罰則卡、金色帽徽。像軍用文件，但**偏平淡，缺少「精選作品」那種一眼被記住的性格**。

現況的具體弱點（請針對這些改）：
1. 首頁四塊磁貼是等重的灰卡，沒有視覺焦點，看不出「按這裡就好」。
2. 命令卡的角色縮在右下角，存在感不夠；大字與角色之間留白過多，畫面鬆。
3. 三段火力（菜鳥／值星／士官長）在視覺上幾乎沒差別，只換了頭像，使用者感受不到「換了一個人」。
4. 罰則倒數只是一個大數字，沒有壓迫感，也沒有完成時的釋放感。
5. 週報卡是一大段白字塞在綠底上，可讀性與分享價值都低。
6. 沒有任何動態、觸覺、聲音的設計，整體像網頁不像 app。

## 4. 參考標竿：從 App Store 精選／Apple Design Award 常客學什麼

不要抄外觀，抄**原則**。每個標竿只取一件事：

| 標竿 | 取什麼 | 用在哪 |
|---|---|---|
| **Carrot Weather** | 有脾氣的角色是整個 app 的靈魂；角色的話跟資料分開排，毒在角色、資料乾淨 | 梗圖卡「上／下」兩段是毒，「大字」與步驟卡是乾淨資訊。這個分離要在視覺上更明確 |
| **Streaks** | 一個畫面一個大動作，圓形／大面積按鈕，按下去有滿足感；顏色就是狀態 | 首頁磁貼、「報告班長，完成」主按鈕 |
| **Things 3** | 留白是設計不是空白；標題字級有明確層級；動畫短、有目的 | 日記頁、點名頁的資訊層級 |
| **Duolingo** | 角色表情跟使用者行為連動，同一個角色至少 4–6 種表情；獎懲有儀式感 | 三位班長 × 4 表情的運用，罰則與登記的儀式感 |
| **Headspace / Calm** | 單色系插畫 + 大面積純色，一眼認得出是誰家的 | 整體色彩系統，讓截圖在 IG 上一眼認得出 |
| **Flighty** | 高密度資訊也能優雅：一個 hero 數字、其他退後 | 日記頂部的三格統計、週報的數字 |
| **Halide** | 觸覺回饋是介面的一部分；每個動作有對應的震動 | 按下命令、倒數每一下、完成登記 |

共同點：**強烈的單一識別色、角色或圖像有性格、每個畫面只要求使用者做一件事、動態與觸覺讓它「像 app」。**

## 5. 設計任務

### 5.1 視覺系統
- 從現有 token 出發（卡其 `#E3DFD0`、墨 `#1B1D1A`、草綠 `#4A5733`、警示紅 `#B3261E`、金 `#D4AF37`），**可調不可換族**：這是軍教片的年代感，不要變成 SaaS 藍。
- 給三段火力各一個明確的視覺差異（不只換頭像）：可以是命令卡底色深淺、字重、邊框粗細、tag 樣式。使用者換班長時，整個 app 的「氣壓」要變。
- 字體：系統字（PingFang TC）為主，若要一個標題字體，必須是 iOS 可內嵌、支援繁中、有粗體的。
- 深色模式完整版本，不是反色。

### 5.2 七個畫面（對照第 13.3 節驗收表）

| # | 畫面 | 必須有 | 這次要改好的 |
|---|---|---|---|
| 01 | 首頁 home | 班長在上、對話框、4 磁貼、3 小鍵 | 磁貼要有主次或有性格；對話框像角色在講話 |
| 02 | 點名 intake | 5 顆星、選項 chips、一顆「是！班長」 | chips 選中狀態要一眼分辨；星星要好按 |
| 03 | 命令卡 cmd | 兩欄、角色不壓字、步驟白卡在下、三顆按鈕（完成／換口令／沒做） | 角色存在感、上中下三段的節奏、4:5 截圖好看 |
| 04 | 命令卡 stop（紅） | 紅卡、verdict=stop 的「不買。／不去。」 | 紅要有份量但不像錯誤訊息 |
| 05 | 登記 log | 登記卡 + 「雄壯！威武！」+ 分享鍵 | 完成的釋放感；分享出去有面子 |
| 06 | 罰則 stand | 紅卡、大數字倒數 | 壓迫感；每一下有節拍；數到 0 的釋放 |
| 07 | 週報 weekly | 單欄文字 + 角色在下 + 分享鍵 | 可讀性；數字 hero 化；截圖像一張成績單 |

另外新增（Capacitor 上架需要）：
- App 圖示 1024×1024（帽徽／班長剪影方向，不要文字）
- 啟動畫面（純色 + 圖示，配合深淺色）
- 空狀態：日記沒有紀錄時的畫面

### 5.3 動態與觸覺（描述即可，不用做動畫檔）
- 命令卡出現：0.2 秒內、一個方向、不彈跳。
- 罰則倒數：每一下一個短觸覺 + 數字微縮放；數到 0 時一個長觸覺 + 卡片顏色從紅轉回。
- 完成登記：一個中等觸覺 + 「雄壯！威武！」有一次強調。
- 換班長：頭像換的同時，命令卡配色跟著換，讓使用者知道整個人換了。
- 全部要能被 `prefers-reduced-motion` 關掉。

## 6. 交付格式（這點很重要，決定能不能直接實作）

請 Claude Design 交付：

1. **七個畫面 + 圖示 + 啟動畫面**，iPhone 尺寸（390×844 為主），深淺色各一套。
2. **設計 token 表**：色彩（含深色對應）、字級階層、圓角、間距、陰影，命名對應現有 CSS 變數（`--khaki --ink --olive --olive2 --signal --mute --line --card`），新增的變數請標明。
3. **每個畫面的規格註記**：哪些是固定尺寸、哪些跟著內容長、哪些要 clamp。
4. **不要交付**：登入頁、設定頁、onboarding、多人功能、任何需要新後端的東西。

交付回來之後，工程端會把 token 直接寫進 `src/styles.css`，版面改動落在 `src/app.tsx` 與 `src/meme.tsx`，頭像介面不動。
