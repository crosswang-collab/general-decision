# 方向 C ｜ 玩具／電玩感

---

## 1. 一句話定位

**柑仔店塑膠兵當班長，整個 App 是他的街機台。**

（不是「軍事玩具」，是「台灣小孩十塊錢一包的塑膠小兵」——這個區別承擔了本方向一半的文化風險，見第 8 節。）

---

## 2. 風格家族

**明確混合兩個：家族 4（Cartoon Network 現代厚線）當骨架 × 家族 9（當代向量吉祥物）當表面處理**，並在兩者之上疊一層**玩具材質語彙**（硬邊高光、模具接縫線、關節圓盤）。

### 為什麼是這個組合，而不是另外七個

| 候選 | 為什麼不是 |
|---|---|
| 家族 1 橡皮管 | 玩具感很強，但研究明列「角色間辨識度低」（全部變圓頭圓手）。本產品最硬的需求是三人一眼可分，橡皮管在這一項只有 2 分。 |
| 家族 5 無輪廓色塊 | 分數高（68）、軍教調性最佳（5 分），但**它是電影感不是玩具感**。玩具的讀感有一半來自「厚描邊＝塑膠件的分模邊緣」，拿掉輪廓線就拿掉了塑膠。 |
| 家族 8 Pixar 立體 | 是最像「公仔」的一個，也是**唯一必須放棄的誘惑**。研究已判定：SVG 沒有可用的網格漸層，這條路只能算圖，一致性從確定性退化成機率。方向 C 需要 12 張以上資產（含第五個 mood），承受不起。 |
| 家族 3 HB 限製作 | 零件化生產模型最優，但線太細（1–1.5%）、大尺寸空洞。方向 C 的主視覺與 App 圖示需要 1024 撐得住。 |

**選家族 4 的三個理由，都是方向 C 專屬的：**

1. **粗等寬外輪廓＝塑膠件輪廓。** 這不是比喻——射出成型玩具的視覺特徵就是「每一片都有一圈明確的邊界」。家族 4 的厚線在 SVG 是一個描邊數字（A 級），它同時買到卡通感、96px 可讀性、與塑膠讀感三件事。
2. **「每個角色分配一個不同基本形並推到極端」是玩具產品線的設計方法論**，不只是卡通的。同系列三款公仔就是靠模具差異賣的。
3. **它撐得住 1024。** 方向 C 的主視覺是包裝卡，卡上的公仔要大。

**家族 9 只借三件事，不借它的調性**：統一圓角半徑（＝統一模具倒角）、色彩節制（3–5 色）、透明去背與圖示安全區。**不借**它的柔軟與對稱親和——那會讓老郭變成公仔，而不是塑膠兵。

### 疊上去的玩具材質層（三件，全部 A 級向量）

- **硬邊高光**：每個曲面左上角一塊白色實心橢圓或圓角三角，**邊緣不羽化**，不透明度 100%，面積約該色塊的 8–12%。這一件事做了，塑膠感就有了八成。
- **模具接縫線**：帽體與頭部各有一條 20 單位的深色直線，從頂點垂直往下到 1/3 處就停。不畫全，畫全就變裝甲。
- **關節圓盤**：肩膀處一個同心圓（外圈＝制服色深一階，內圈＝制服色）。只在肩膀做一處，不做手肘手腕——bust 構圖只看得到肩，而且做多了會變機器人。

## 3. 角色造型規則

沿用研究 §5.1 的 1024×1024 master 格線（眼線 Y470、肩線 Y800、眼距 250），以下是方向 C 的覆寫值。

| 參數 | 規格 | 說明 |
|---|---|---|
| **頭身比（bust 內）** | 頭高佔畫布 **68%**（非原 55–65%） | 玩具的大頭比例。這個數字三人共用，不得個別調整 |
| **頭形** | 阿良＝正圓 D600；黑面＝圓角方 600×600 R90；老郭＝長倒梯（上 580／下 420／高 660、R60） | 直接採用研究的分配，它已通過黑剪影測試的設計 |
| **眼睛** | 阿良：正圓眼白 D140＋圓瞳 D56＋左上高光 D24<br>黑面：橫膠囊 150×44＋實心瞳<br>老郭：**老花眼鏡滑到鼻尖**（兩個 R20 圓角矩形 150×100，鏡片 30% 不透明，眼睛從鏡片上方露出） | 老郭改老花眼鏡、不用墨鏡——見第 8 節，墨鏡＋哨子＋方下巴是美式教官的固定組合 |
| **眉** | 阿良 130×20 細彎梯形／黑面 170×42 粗直／老郭 190×52 極粗斜＋兩道白毛線（白毛線寬 24，不得更細） | |
| **線條** | 外輪廓 **34 單位（3.3%）**、內部結構線 20（2.0%）、裝飾線下限 24。全部**等寬**，端點 round | 比研究建議的 31 再粗一級，換取塑膠件邊緣的分量 |
| **描邊色** | 不用純黑，用 `--outline #0D0F0C`；制服上的內部線用制服暗階 `#3D5320` | 純黑在高飽和環境會顯得髒 |
| **用色數** | 每個角色 **6 色上限**：膚、膚暗、制服、制服暗、描邊、金。加上「共用三色」：塑膠高光白、值星紅、名牌白 | 硬上限。第 7 色必須刪掉別的 |
| **陰影** | **一階，硬邊，固定光源左上 45°**。陰影色＝該色明度 −18%、飽和 +6%。**禁止漸層、禁止柔邊、禁止環境光** | 這是「射出成型件」與「繪畫」的分界線 |
| **臉的構造規則（寫進發包文件）** | 權威來自眉毛與法令紋。**下巴與下顎不承擔任何表情**。顴骨最寬、鼻樑起點低而短、不挖眼窩 | 直接引用文化研究，這條在方向 C 最容易被違反 |

### 表情：五個 mood，不是四個

方向 C 額外要求新增 **`soft`**（罰則結束後、日記空狀態使用）：眼神別開、嘴平、或直接 3/4 背面。

理由不是美學，是結構性的：電玩語彙裡沒有「藏」這個動作，五個滿幅度表情會把班長變成霸凌者。這一張圖是「情義」在方向 C 的唯一載體。它讓資產從 12 張變 15 張——零件化之後多這三張的成本接近零（多一組嘴＋一組眉），但如果不做，第 8 節的第 4 條風險無法緩解。

**表情＝零件替換**：3 個頭＋3 個身＋5 組眉＋5 組嘴＋3 組配件 = **19 個零件組出 15 張**。眼線、肩線、線寬一致不是檢查項目，是結構保證。

### 剪影補強（不可省略）

每人一個跨出頭部外輪廓 ≥ 48 單位的凸起或凹口：

- 阿良：帽子上翹、帽後一撮呆毛凸 70
- 黑面：帽體最厚最方（+60），值星帶讓右肩線抬高 50、肩線刻意不對稱
- 老郭：白髮向兩側外翻各 60，哨繩在頸部形成深 60 的 V 凹

## 4. 三段火力：整個 App 的氣壓怎麼變

方向 C 的核心主張是：**換班長不是換頭像，是換遊戲難度**。三個 level 各自定義一整組 `:root` 變數，切換時全畫面同步變。這在 `design/build.mjs:16/23/30` 已有先例（每階的 cmd/r/bw/w/ls/stripe），方向 C 把它從設計檔搬進 `src/styles.css`。

| 變數 | lv0 阿良 | lv1 黑面 | lv2 老郭 |
|---|---|---|---|
| `--stage` 主畫布底 | `#EDE3C4` 亮卡紙 | `#E3D7B4` 中 | `#C9BC96` 壓暗 |
| `--hud` HUD 面板底 | `#1E5AD6` 藍 | `#152B3F` 深藍 | `#101418` 近黑 |
| `--hud-lines` 等級刻度 | 1 格亮 | 2 格亮 | 3 格亮＋滿格閃 |
| `--frame` 卡片邊框寬 | 2px | 3px | 4px |
| `--depth` 按鈕厚度 | 3px | 4px | 6px |
| `--tick` 倒數節拍 | 1000ms | 600ms | 500ms（已存在於 `officers.ts`） |
| `--shake` 數字回彈幅度 | scale 1.08 | 1.16 | 1.24 |
| `--burst` 完成粒子數 | 12 | 24 | 36 |
| `--scan` 掃描線疊層 | 無 | 無 | opacity .06 橫線 |
| 角色佔梗圖卡右欄的高度 | 88%（頭頂離框 12%） | 96% | **104%（帽頂被切掉一點）** |

**最後一列是整套機制的重點**：三人的眼線與肩線鎖死，壓迫感全部來自**留白被吃掉的程度**，而不是把角色放大或抬高。這同時滿足研究的槽位契約，也避開「仰角英雄鏡位」。

**還有一個非視覺的分級**：切換時的音效與觸覺。阿良的切換是一記 `selectionChanged`；老郭是 `impact .heavy` ＋ 掃描線在 180ms 內掃過一次。使用者不看畫面也知道自己把難度調到哪一格。

## 5. 調色盤

### 與現有 token 的關係：**四個全部「調整」，零個「取代」，新增四個。**

判斷依據是研究的不對稱性結論——金風險最低、紅次之、卡其居中、草綠最高——所以四色的調整幅度刻意不一致：金拉滿、草綠最保守。

| token | 現值 | 方向 C（light） | 方向 C（dark） | 動作 | 理由 |
|---|---|---|---|---|---|
| `--khaki` | `#E3DFD0` | **`#EDE3C4`** | **`#14171A`** | 調整（往暖黃 +12 飽和） | 從「公文紙」移到「玩具包裝卡紙」。這是最小的一步，但它讓整個畫面脫離文件感 |
| `--ink` | `#1B1D1A` | `#1B1D1A` 不動 | `#EDE7D6` | 保留 | 沒有理由動 |
| `--olive` | `#4A5733` | **`#5C7A2E`** | `#6B8C36` | 調整（飽和 27%→45%，明度 +12） | 塑膠軍綠。**上限就到這裡**——再往黃會變萊姆綠，再往亮會失去軍綠身分 |
| `--olive2` | `#39452A` | **`#3D5320`** | `#4A6127` | 同步重算 | 一階硬邊陰影用色 |
| `--signal` | `#B3261E` | **`#E03B1C`** | `#FF4A24` | 調整（往橘偏 +8°，明度 +18） | 從 Material error red 移到「警報／爆炸」。這一步直接針對「倒數沒有壓迫感」 |
| `--gold` | `#D4AF37`（目前只存在於 `design/build.mjs`） | **`#FFC42E`** | `#FFD45C` | 調整＋正式進 `:root` | 四色中提亮幅度最大的，風險最低 |

### 新增（方向 C 專屬，共四個）

| token | 值（light / dark） | 用途 | 面積上限 |
|---|---|---|---|
| `--arcade` | `#1E5AD6` / `#2A6BE8` | HUD 面板底、選中態、等級刻度 | 12% |
| `--void` | `#101418` / `#0A0C0E` | lv2 的 HUD 深底、罰則卡暗角 | 依 level |
| `--plastic` | `#FFFFFF`（兩者相同） | 硬邊高光。**不透明度必須 100%，不得用 alpha** | 每個色塊 8–12% |
| `--outline` | `#0D0F0C` / `#0D0F0C` | 所有描邊。深色模式**不翻轉**——塑膠件的邊在暗處還是暗的 | — |

### 對比實測（我算過，非估計）

| 組合 | 對比比 | 判定 |
|---|---|---|
| 白字 on `--olive #5C7A2E` | **4.85:1** | 過 AA 內文（4.5）。但餘裕從原本的 ~7:1 掉到 4.85，**任何再加飽和的要求都會掉出門檻** |
| 白字 on `--signal #E03B1C` | **4.37:1** | **不過 AA 內文**。只能用在 ≥24px bold 的大字（AA Large 3:1）。罰則卡的大數字 OK，`bot` 那行小字必須改用 `--ink` 或加 `--void` 底條 |
| ink on `--gold #FFC42E` | **13.2:1** | 過 AAA |
| 白字 on `--gold` | **1.59:1** | **金色上絕對不能放白字。** 寫成硬規則 |
| 白字 on `--arcade #1E5AD6` | **6.01:1** | 過 AA |

`prefers-contrast: more` 的處置：`--signal` 退回 `#B3261E`、`--olive` 退回 `#4A5733`、關閉所有掃描線與高光。也就是**高對比模式下，方向 C 退化成接近現況的樣子**。這是誠實的，也是第 8 節第 6 條風險的來源。

### 一個測試衝突，先講

`tests/e2e/system.spec.ts:8` 硬驗 dark `--khaki` = `rgb(23,24,19)`、`:15` 驗 light = `rgb(227,223,208)`。**方向 C 改 `--khaki` 就會讓這兩行紅燈。** 這是全專案唯一被硬驗的色值，改動範圍是兩行字面值，但需要有人改測試。若不願動測試，`--khaki` 就必須保留原值，方向 C 的「玩具卡紙」只能靠 `--stage`（新 token）在 body 之上再鋪一層來達成——可行，但多一層 DOM 或多一條 `body::before`。

## 6. UI 怎麼跟著變

前提：**§9 八條規則我全部遵守，不申請豁免。** 尤其是規則 2（梗圖卡兩欄 `1fr 38%`、角色不壓字）——電玩 UI 最想做的事就是把角色當背景、HUD 疊在上面，那是方向 C 最大的誘惑，也是最該被擋下的一條。角色壓字之後，文字可讀性、4:5 截圖、與「班長是說話者」的語意全部一起壞掉。下面四個畫面都在既有 grid 內完成。

### 6.1 home — 待機／選人畫面

- **`.officer` 區**（規則 1，位置不動）改成 **HUD 頭像框**：`--hud` 深底、四角斜切 12px、左側 5.75rem 頭像方框保留但加 2px `--gold` 內描邊、右側 rank/name 用等寬字、name 下方加一條**三格等級刻度**（第 N 格填 `--gold`）。
- `title='點頭像換班長'` 的提示從一行灰字改成刻度條兩側的 `◀ ▶` 兩個 44×44 觸控區——**它們仍然只是呼叫 `cycleOfficer`**，不新增狀態。
- **四大磁貼**：`.tile` 從 1px 邊框白卡改成 `--card` 底、**2px `--outline` 描邊 ＋ `box-shadow: 0 var(--depth) 0 var(--olive2)`** 的實體鍵；`:active` 時 shadow 歸零 ＋ `translateY(var(--depth))`。半徑從 8px 改 18px。`.tile b` 的 2rem 數字改 `--gold` ＋ 2px `--outline` 描邊。
- **三小鍵**：半徑 999px 膠囊，橫捲行為不動（規則 7 的 e2e 硬驗 `flexWrap:nowrap` / `overflowX:auto` 照過）。
- 背景：`--stage` 上疊一層極淡的**斜向平行條紋**（45°、間距 48px、opacity .04）。**不是放射狀**——放射狀是旭日旗，見第 8 節。

### 6.2 cmd — 任務卡

grid 仍是 `1fr 38%`、`aspect-ratio: 4/5`、子節點仍恰為 `['tag','txt','face']`（`tests/unit/avatar.test.tsx:63-70` 照過）。

- **`.tag`** 從半透明小字變成**左上角斜切的 HUD 標籤條**：`--void` 底、`--gold` 等寬字、右端 45° 斜切。文字內容不動（「決斷連 · 一個口令一個動作」）。
- **`.txt` 左欄**：`top` 一行小字；`big` 是主角——保留現有 `clamp()`（規則 3 不動），但把現有的五向 `#000` text-shadow 換成 **3px `--outline` 描邊 ＋ 6px 單向硬位移陰影**（`--void`），字重 900。
- **`.face` 右欄**：`align-self: end` 不動。角色**背後**加一塊斜向條紋背板（`--olive2`，圓角 18px，比角色寬 4px），讓角色從卡片底色裡「跳」出來。背板是 grid 內的兄弟節點的背景，不是絕對定位。
- **`.steps` 白卡**（規則 4，分離、不放梗、不放罵）：白卡保留，加 2px `--outline` 描邊 ＋ `0 3px 0` 硬陰影，`▸` 前綴保留但改 `--arcade` 色。**文案零改動、零毒性、不加任何遊戲化詞彙。** 這一格是方向 C 唯一完全不娛樂化的區域，它是「這個 app 的建議是真的」的證據。

### 6.3 stand — 罰則倒數

這是方向 C 最需要克制的一格。

- 卡片 `tone="red"`：底色 `--signal`，四邊往內 120px 的**暗角**用 `--void` 徑向壓暗，**隨 `--tick` 節拍脈動**（opacity .0 ↔ .18）。壓迫感來自時鐘，不是來自班長。
- **大數字**：字級進到 clamp 上限，`--plastic` 白字 ＋ 4px `--outline` 描邊。每 tick 做 `scale(1) → scale(var(--shake)) → scale(1)`，120ms，back-out。每 tick 一記 `impact .light`，強度在序列內遞增。
- **班長**：`punish` 表情，但**姿態是抱胸、視線別開**。不放大、不逼近、不破框、不指向使用者。punish 的嘴必須是吼（嘴角向下），不能是笑弧。
- **不放 `GAME OVER`、不放 `FAILED`、不放 ✕。** 倒數完成後的文案維持既有的「登記」語氣。方向 C 在這一格主動放棄電玩最標準的一個畫面，理由在第 8 節第 4 條。
- `bot` 那行小字（`p.line`）因為白字在 `--signal` 上只有 4.37:1，必須加一條 `--void` 底條。

### 6.4 weekly — 結算畫面

- `.meme.wide` 單欄、自動高度（規則 6、`weekly.spec.ts:33-34` 的單欄斷言照過）。
- 服從率從 `.stats` 的一格升級成 hero：`--gold` ＋ `--outline` 描邊、字級 3rem 以上、**進場做 400ms count-up**（`prefers-reduced-motion` 下直接顯示終值）。
- 三格 `.stats` 改成三條水平 HUD 條（`--arcade` 底、`--gold` 填充）。
- 底部固定 104px 頁尾：金色帽徽 ＋「決斷連」＋ 短網址。分享圖沒有頁尾＝免費傳播零導流。

## 7. 主視覺

**一張柑仔店的塑膠兵吊卡。**

- **畫面比例**：主圖 1:1（社群）＋ 1200×630 橫式裁切（OG）＋ 直式 1080×1350（IG）。三種裁切共用同一個中心。
- **背景**：泛黃的**印刷卡紙**——`#EDE3C4` 底 ＋ 可見的紙纖維雜點 ＋ **套色偏移 1.5px**（青版往左上偏）。年代感全部押在這裡，而不是押在角色身上。這直接執行文化研究的「原則一：風格從在地印刷品長出來」。
- **主體**：三個公仔**等距並列**在同一張卡紙上，各自裝在一個**吸塑泡殼**裡（泡殼＝白色 15% 不透明的圓角矩形 ＋ 一道 45° 硬邊高光斜線）。三人眼線與肩線**絕對同高**。
- **氣壓遞增**：泡殼背板由左到右 `#EDE3C4` → `#5C7A2E` → `#101418`；阿良留白最多，老郭的帽頂**頂到泡殼上緣**。三人表情分別是 `idle` / `bark` / `punish`——讀成「同一個動作被三種人執行」，而不是三個角色的合照。
- **卡紙頂端**：打孔掛勾（一個圓角矩形 ＋ 一個圓）。這一個零件是整張圖的識別錨點，也是「這是玩具不是軍隊」的宣告。
- **卡紙底端**：一條金色刻度線，三個 tick，第 2 個高亮（對應預設 level 1）。刻度線把「合照」翻譯成「選擇器」。
- **文字**：一句 app 內真實語料當標語（例：`阿財魯肉飯。十二分鐘。`），繁中粗黑，套色偏移同步。**不放** App Store 徽章、不放手機外框、不放功能條列。
- **紅色全圖只出現兩次**：黑面的值星帶、老郭的哨繩。兩點連成斜線，把視線帶到右邊。

**為什麼是吊卡而不是三角構圖或群像**：因為三位班長不是隊友，是同一顆旋鈕的三格。玩具包裝天然就是「同系列三款」的語法——它一次解決了「等距並列」「三人不互動」「可選擇」三件事，而且不需要任何說明文字。

**明確不做的備案**：三段曝光疊影（語意最準但小尺寸必糊）、以及任何有「G.I. Joe 式吸塑卡」讀感的美式包裝設計——見下一節。

## 8. 這個方向的代價

這一節寫得比前面七節加起來重要。以下每一條我都認為是真的，不是形式上的免責。

### 8.1 它稀釋產品唯一的笑點（最嚴重，且無法靠執行力補救）

決斷連的趣味來源是**反差**：嚴肅的軍事語氣去處理「中午吃什麼」這種瑣事。反差要成立，需要一個**不好玩的框**——嚴肅的框裝進瑣碎的內容，落差就是笑點。

方向 C 把框也變好玩。於是結構從「嚴肅框 × 瑣碎內容」變成「好玩框 × 好玩內容」——落差歸零。使用者的解讀會從「這個 app 有病，我喜歡」滑向「這是一個軍事主題的小遊戲」。前者會被轉發，後者不會，因為它不再讓人意外。

**這是方向 C 的結構性代價，不是程度問題。** 娛樂化研究自己的結論就寫在最後一行：「要動的是回應密度，不是主題。」方向 C 動的是主題。

**部分緩解**：把 `.steps` 白卡與所有命令本體維持 100% 零娛樂化（6.2 已寫入），讓「好玩的框裡裝著一個認真的建議」變成新的反差來源。但這個反差比原本的弱——它需要使用者讀到第二層才感覺得到，而原本的反差在 0.3 秒就成立。

### 8.2 它損害產品的工具可信度

這個 app 會給出真實可執行的建議：真實店名、真實步驟、真實分鐘數，還會存日記、算服從率、出週報。這些功能要有用，前提是使用者**相信它**。

電玩 HUD 會把真實資訊讀成遊戲道具。「阿財魯肉飯 · 十二分鐘」放在能量條和斜切面板之間，看起來像隨機生成的任務文本，而不是一個真的可以去吃的地方。而它**確實是**真的——這是產品最有價值的部分，方向 C 讓它看起來最不值錢。

第二層損害：使用者對「罰則」的認真程度。罰則的作用是建立賭注。遊戲裡的懲罰是零成本的（重來就好），現實的罰則不是。把倒數畫面做成街機畫面，等於告訴使用者「這只是遊戲，不做也沒關係」——而不做就是這個 app 唯一的失效模式。

### 8.3 對文化轉譯研究的哪些風險特別暴露

方向 C 在九個方向裡對這份研究的曝露最高。逐條對照：

| 研究中的風險 | 方向 C 的曝露 | 我的處置 |
|---|---|---|
| **「V 字身材、三角肌 ＝ G.I. Joe 化 ＝ 軍國主義化」**（§3） | **最高。** 「可動公仔」在視覺文化裡的原型就是 G.I. Joe。做塑膠兵這件事本身，就是在走向研究明確標紅的那個終點 | 造型規則鎖死「頸比頭窄、肩線的方是衣服的方不是肌肉的方」；主視覺用**台灣柑仔店袋裝小兵**的包裝語法（打孔吊卡、泛黃卡紙、套色不準），而非 Hasbro 吸塑卡。**但這是一條很細的線，執行時會不斷被拉向錯誤那側，因為錯的那側更好看** |
| **「頭後放射狀光芒 ＝ 旭日旗」**（§5.A.2） | **極高。** 放射狀爆閃是電玩 UI 的第一反射——命中、升級、勝利、選人確定，全部用它 | 全案**禁止放射狀**，一律改用 45° 斜向平行條紋。praise 的金色線維持「短線、只在兩側、成對、≤4 道」 |
| **「五角星」**（§2.1） | 中。電玩的等級／評價標準符號就是星星（★★☆） | 等級表示改用**三格刻度條**，不用星。帽徽用虛構部隊徽（十二道短放射芒＋圓框，明確不是國徽本體、不是五角星） |
| **「多人整齊列隊 ＝ 集體符號」**（§5.A.4） | **高。** 選人畫面、角色圖鑑、公仔系列圖，全部是「一排一樣的人」 | 主視覺三人分裝在三個泡殼裡、背板明度不同、表情不同——靠**分隔**而非**並列**。App 內永遠只顯示一位 |
| **「仰角英雄鏡位」**（§5.A.1） | 高。格鬥遊戲選人畫面的預設就是仰角 | 全案固定平視或略俯視；氣壓靠留白被吃掉，不靠抬高 |
| **「攻擊性由身體承擔 ＝ 霸凌」**（§5.B.9、B.11） | **最高。** 街機的核心是打擊感——震動、衝擊、破框、逼近。方向 C 的每一個動態衝動都指向這裡 | 罰則的壓迫感只來自**時鐘**（暗角脈動 ＋ 節拍）；班長抱胸別過頭。**明確放棄了方向 C 最有效的一種爽感** |
| **「GAME OVER ＝ 純羞辱」**（§5.B 整節的延伸） | **高。** 電玩的失敗畫面沒有「情義」這個語彙 | 不放任何失敗大字；新增第五個 `soft` mood。但**電玩語法本身沒有「別過頭」這個動作**——我是在一個不支援這個語意的語言裡硬造一個詞 |
| **「莊嚴化的色彩 ＝ 極權海報配方」**（§5.A.6） | 中。方向 C 提高了飽和與對比，正好往「飽和草綠＋高對比金＋銳利印刷」靠 | 靠主視覺的**印刷缺陷**（套色偏移、紙纖維、略髒的金）抵銷。研究說「懷舊會殺死莊嚴」，這是方向 C 唯一的解藥，而它只在主視覺生效，**App 內部因為要高對比與清晰，用不上這帖藥** |
| **「惡意截圖測試」**（§5.C） | 方向 C 的 `punish` 畫面**是全案最可能沒通過這一關的單張圖** | 必須在定稿前實跑這個測試。**若不過，方向 C 應該被否決，而不是修改** |

### 8.4 它會製造一個兌現不了的遊戲化承諾

有 HUD、有等級刻度、有粒子、有結算畫面，使用者就會預期：進度、解鎖、收藏、商店、排行榜。目前產品一項都沒有。

娛樂化研究裡那句「沒有去處的慶祝是煙火，有去處的才是玩具」正好是這個問題——而補上「去處」意味著要做一整套 meta-game（收集、等級、解鎖），產品範圍會從「按一顆鍵」爆炸成「養成系統」。第 3 天使用者會問「然後呢」，而答案是沒有。

方向 A、B 不會遇到這個問題，因為它們不承諾遊戲。

### 8.5 無障礙退化後幾乎不剩東西

方向 C 的價值高度集中在**動態、飽和、與觸覺**。在三種系統設定下它會被逐層剝光：

- `prefers-reduced-motion`：粒子、count-up、回彈、掃描線全關 → 只剩靜態色塊
- `prefers-contrast: more`：飽和退回原值、高光關閉 → 顏色回到現況
- iOS Dynamic Type 拉到最大：clamp 上限吃掉大數字的戲劇性

三者同時開啟的使用者，拿到的是一個**沒有動態、不飽和、比現況更醜**的 app——因為方向 C 為了容納 HUD 而增加的邊框、斜切、面板在靜態下只是雜訊。

這不是理論風險。三十歲以上、當過兵的目標族群，開啟 reduced-motion 與加大字級的比例不低。

### 8.6 上架的兩個具體風險

- **可能被要求歸類到 Games。** 外觀像遊戲但沒有遊戲機制的 app，審核時的分類爭議是真的。一旦被歸到 Games，它就要跟真遊戲競爭排名，而它會輸。（此條我沒有把握確切的審核實務，**需要查證**。）
- **2.3.3 的解讀風險升高。** 截圖第 3 張（三段火力合成圖）在方向 C 會長得很像遊戲廣告。規則本身允許文字疊層，但「畫面部分必須是真實 app 畫面」的判定在遊戲風格下更容易被挑。

### 8.7 明確的否決條件（建議寫進評比表）

方向 C 應該被淘汰，如果下列任一成立：

1. **惡意截圖測試不過**：`punish` 單張脫離脈絡後讀起來像霸凌梗圖或軍國主義海報。
2. **「哪一國的兵」測試不過**：5 個當過兵的人看 96px 縮圖、無說明、2 秒內回答，未達 5/5 答「台灣」。方向 C 因為 G.I. Joe 引力最強，這一關的失敗機率最高。
3. **決策者無法接受 8.1**：如果「反差是這個產品的核心資產」被判定為不可讓渡，方向 C 在定義上就不成立，不需要看執行細節。
4. **不打算做 Capacitor 原生殼**：方向 C 的回應密度有三分之一押在觸覺上，`navigator.vibrate` 在 iOS Safari 無效。沒有原生殼，方向 C 會退化成「很吵的靜態畫面」——比現況更糟。

## 9. 生產可行性

### 9.1 純 SVG 能做到什麼程度

**角色資產：100% 純 SVG，不需要繪師、不需要算圖。**

方向 C 選的骨架（家族 4）與表面處理（家族 9）在研究的判定表裡都是 **A+ 級**。額外疊的三件玩具材質層也全部是 A 級：

| 元素 | SVG 作法 | 級別 |
|---|---|---|
| 厚等寬外輪廓 | 同一路徑先粗描邊墊底、再填色疊上（兩層） | A |
| 硬邊高光 | 白色 `<ellipse>` / 圓角路徑，無濾鏡 | A |
| 一階硬邊陰影 | 一個填充路徑，用 `clip-path` 切在色塊內 | A |
| 模具接縫線 | `<line>`，等寬描邊 | A |
| 關節圓盤 | 兩個同心 `<circle>` | A |
| 三種頭形 | 正圓／圓角矩形／梯形路徑 | A |
| 老花眼鏡 | 兩個圓角矩形，鏡片 `fill-opacity=.3` | A |

**唯二需要注意的：**

- **掃描線與網點（lv2）**：`<pattern>` 原生可做，但 96px 必定摩爾紋。必須輸出兩個 LOD：1024 完整版、96 簡化版（刪除所有 <24 單位的線、外輪廓加粗到 3.5%、關閉網點）。
- **粒子爆炸**：不是 SVG，是 DOM 或 canvas，需要 JS。約 120 行，含 `prefers-reduced-motion` 分支。

**仍然需要一個人做一次判斷**：阿良的 idle 應該先由**台灣繪師**手工定稿一張（turnaround），當作風格基準與文化錨點，**不要用生成模型**。文化研究的警告在方向 C 特別致命——模型看過的「美國玩具兵」比「中華民國草綠服」多幾個數量級，而且它畫得好看，所以你會通過它。定稿之後，其餘 14 張由零件重組產生，一致性是結構保證。

### 9.2 落地路線：改寫 `avatarSvg()`，介面零改動

不走 `.webp` 資產路線。理由：`src/avatar.tsx:8` 的 `.webp` 寫死、無 `object-fit`（非正方形會拉伸變形）、`onDark` 對 raster 完全失效（深色模式下 raster 頭像不變色）。方向 C 的角色要跟著 level 換色、跟著深色模式換描邊環境，走 inline SVG 才做得到。

改寫 `avatarSvg()` 回傳字串，`AvatarProps` / `assetUrl` / `Avatar` 全部不動。要滿足的既有契約：

- 以 `<svg` 開頭、`</svg>` 結尾，含 `viewBox="0 0 120 120"`（`design/build.mjs:82` 依賴這個字面值做胸像裁切）
- 不得出現 `undefined` / `NaN`
- `onDark=true` 含 `fill="none"`；`false` 含 `url(#bgG)`
- **必須含四個字面值**：`#C0392B`、`#8C8C8C`、`rotate(-7 60 36)`、`#5DADE2`

### 9.3 已知的測試衝突（三處，全部具體）

1. **`rotate(-7 60 36)` vs 帽子傾角 15°**（`tests/unit/avatar.test.tsx:39-44`）
 剪影研究要求阿良的帽子從 7° 加大到 15°，否則在 96px 是 0.6px 的位移，等於零。但單元測試硬驗 `-7`。
 **解**：帽子用 `rotate(-15 …)`，把 `rotate(-7 60 36)` 用在**呆毛**或**帽徽**上（它仍是真實使用的變換，不是為了過測試而塞的死碼）。零測試改動。

2. **`--khaki` 色值**（`tests/e2e/system.spec.ts:8` / `:15`）
 方向 C 改 `--khaki` → 兩行紅燈。改兩個字面值即可，但需要有人改。若不願改，`--khaki` 保留原值、另開 `--stage`。

3. **`.meme` 子節點恰為 `['tag','txt','face']`**（`tests/unit/avatar.test.tsx:63-70`，className 字串完全相等）
 方向 C 想加的斜向條紋背板**不能是第四個子節點，也不能給 `.face` 多加一個 class**。必須做成 `.face` 的 `background-image`（CSS `repeating-linear-gradient`）或 SVG 內的一層。這是可行的，但要知道這條線在哪。

### 9.4 工作量與關鍵路徑

| 項目 | 需要什麼 | 阻塞誰 |
|---|---|---|
| 阿良 idle 手工定稿 | **台灣繪師，一張** | 其餘全部 |
| 19 個零件建模（純 SVG 路徑） | 一個人，照 §3 格線 | 15 張表情 |
| `avatarSvg()` 改寫 | 工程，約 300–400 行字串 | App 內所有畫面 |
| token 改寫 ＋ 三階變數 | 工程，`src/styles.css` ＋ 兩行測試 | UI 四個畫面 |
| 粒子／count-up／回彈 | 工程，~120 行 JS ＋ reduced-motion 分支 | 完成演出 |
| 觸覺 | **Capacitor 原生殼（決策前置）** | 若不做，方向 C 降級 |
| 繁中 display face | 授權查證。街機／點陣風的可商用繁中字檔選項很窄（開源點陣繁中字有，但**確切授權條款與 iOS 內嵌可行性我沒有把握，需要查證**） | 大字的性格 |
| 主視覺吊卡 | 印刷缺陷層（套色偏移、紙纖維）可用 SVG filter 或一張點陣疊層 | 不阻塞上架 |
| 1024 App 圖示 ＋ Dark ＋ Tinted | 帽徽構圖，不放臉 | **唯一「進不了 binary 就不能送審」的素材** |

**不需要**：3D、算圖、AI 生成最終資產、外部設計系統。

**一句話的產能結論**：方向 C 的美術工作量比其他方向高的部分不在角色（零件化之後三個方向差不多），而在 **UI 層的變數矩陣（三階 × 十個變數）與動態實作**。角色是可控的；氣壓分級是真正的成本。
