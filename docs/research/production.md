## 一句話回答

**可以，而且 UI 那一半幾乎全部可以。角色那一半要看你選哪個風格方向——如果選的是向量原生的家族（4、5、9），Claude Design 做得到而且品質天花板很高；如果選的是需要筆觸、質感、立體的路線，它做不到，而且勉強做會很難看。**

判斷這件事的唯一標準是：**這張圖能不能用「圓、圓角矩形、梯形、等寬描邊、硬邊色塊」描述出來？** 能，Claude Design 就是最快最穩的做法；不能，它連及格都達不到。三個候選方向（A、B、C）在骨架上都選了家族 4（CN 厚線），所以三個方向的角色**都落在 Claude Design 的能力範圍內**——這不是巧合，是那三份提案在做風格選型時已經把生產可行性算進去了。

另外一個事實先講清楚：**這個專案已經在用 Claude Design 了。** `design/` 底下的十二個 `.dc.html`（Main、Cmd、CmdStop、Intake、Log、Stand、Weekly、Icon、Splash、Tokens）就是 Claude Design 的畫布檔，`design/build.mjs` 是它的生成器。所以問題不是「能不能用」，而是「這次要把它的職責推到多遠」。

## 能力切分表

判定標準三級：**做得到**＝它的原生輸出格式就是這個東西；**勉強但會差一截**＝技術上產得出來，但品質或一致性不到可交付水準，需要人補；**做不到**＝輸出格式根本不對，硬做等於用錯工具。

### A. UI 與版面

| 工作項 | 判定 | 理由 |
|---|---|---|
| 七畫面 UI 設計稿（home / intake / cmd / cmd-stop / log / stand / weekly） | **做得到（強項）** | 這就是它的本職。而且這七張**已經存在**於 `design/*.dc.html`，不是從零開始，是改版 |
| 空狀態五張（日記空／週報未到／API 掛／附近沒開的／定位被拒） | **做得到** | 版型是「頭像＋一句話＋一顆按鈕」，文案第 11 節已寫好，零新資產 |
| CSS token 表（十個現有 + 新增的 `--gold` / `--pop` / `--alarm` / `--paper`） | **做得到（強項）** | 它輸出的本來就是 CSS。而且它能同時產出「token 表視覺稿」與「可貼進 `src/styles.css` 的變數宣告」兩份，這是它相對任何設計工具的結構性優勢 |

### D. 它不做、也不該做的

- **不做文化判斷。** 它不會知道金色五角星是錯的（中華民國是青天白日，五角星是解放軍／蘇聯系統）、不會知道值星帶方向翻了、不會知道 high-and-tight 是美國海陸標記。**你給它什麼幾何它畫什麼幾何，它沒有「這看起來像美國兵」的直覺。**
- **不做取捨決策。** 「38% 欄寬要不要放寬到 42%」是產品層規則的裁決，不是設計題。
- **不做驗收。** 黑剪影測試、「哪一國的兵」測試（5 個當過兵的人、96px、2 秒）必須由人跑。
- **不保證跨次一致。** 這是最重要的一條：**它的一致性來自你要求它產出的結構，不是來自它的記憶。** 要求函式＋格線常數，一致性是結構保證；要求十二張圖，一致性是擲骰子。

## 關鍵判斷：純 SVG 的角色，能不能做到「好看」

### 能，但「好看」在這裡有一個明確的定義

如果「好看」＝**Dexter's Laboratory / Johnny Bravo / Powerpuff Girls 那種好看**——厚等寬黑描邊、巨大簡單的眼睛、三到六個純色、零陰影或一階硬邊陰影、每個角色一個被推到極端的基本形——那麼**純 SVG 不只是做得到，它是做這件事最正確的工具**。那個畫風的全部形狀語彙就是 SVG 原語，一對一對應，沒有任何一項需要近似。

這是九個風格家族裡**唯一一次「美學上最激進」與「生產上最便宜」重合**的情況。其他更誇張的路線（rubber hose 的紙紋水彩、Pixar 的體積光）都要付算圖或繪師的錢。

而且它比繪師與 AI 算圖多拿到兩樣東西：

1. **十二張的一致性是結構保證，不是檢查項目。** 它們共用同一條頭部路徑、同一條格線（眼線 Y、肩線 Y、眼距、線寬），不是十二次獨立的創作。原 `CHARACTER-BRIEF.md §4` 驗收表裡最難過的「三人眼線與肩線一致」「配件沒多沒少」，在這條路上不可能失敗。
2. **兩個 LOD 是免費的。** 等寬描邊＝一個數字。96px 版可以「把外輪廓從 3.3% 加粗到 3.8%、刪掉所有 <24 單位的線」而不重畫任何東西。變寬線家族、raster、算圖，**全部做不到這件事**。

### 什麼條件下會失敗——六條，每一條都是真的

**1. 風格方向中途滑向需要質感的一端。**
只要有人說出「線條有筆意一點」「加點紙紋」「皮膚有點立體」，這條路就從 A 級掉到 B/C 級，而且**不是變醜，是變成必須重做**。變寬線一旦外框化，96px LOD 就死了；立體皮膚需要網格漸層，SVG 沒有。**這三句話要寫進發包文件當禁令，不是當偏好。**

**2. 生成方式錯了：分十二次畫，而不是寫一個函式。**
這是最容易犯的錯，因為它比較直覺。分十二次的結果與 ChatGPT 生 12 張 PNG 沒有本質差別——每一張的線寬、眼線、配件都重新擲骰子，而驗收表變成人工彌補結構缺陷。**正確做法：要求 Claude Design 產出 3 頭 + 3 身 + 4–5 組眉 + 4–5 組嘴 + 3 組配件 = 17–19 個零件，由 `avatarSvg(lv, mood)` 組合。**

**3. 剪影差異不夠，三個人在 48px 全黑並排時分不出來。**
這是**唯一一個會讓整個方向作廢的假設**，而它與工具無關——換繪師來畫也一樣會死。現行設定的三人差異幾乎全在顏色與配件：阿良的歪帽 7° 在 96px 是 **0.6px 的位移，等於零**；膚色三階的灰階值只差 9–10（門檻是 20）。
**成本只有三個純黑剪影，半小時。這是第一個要做的事，不是最後一個。** 過不了，只有兩條路：加大帽子／髮／肩的差異，或回頭動下顎（但動下顎就是把台灣臉換成西方臉，方向 B 的前提會消失）。

**4. 為了 96px 可讀，把在地細節砍掉了。**
名牌中文、燙線、曬痕、內衣白領——全部低於或接近 24 單位的門檻。只要驗收時「為了清楚」把它們砍掉，你會得到三個很好看的美國卡通兵，而且**看起來完全沒問題**。
**防線寫成規則：「96px 版可刪，512/1024 版不可刪」，而不是「不清楚就刪」。**

**5. 角色的色票沒有接上 CSS 變數。**
現行 `src/avatar.tsx` 的所有顏色都是 SVG 屬性字面值（`#EFC9A6`、`#33402A`、`#1F1F1C`…），沒有 `currentColor` 也沒有 `var()`。後果是**深色模式下頭像完全不變色**，而且 avatar 的 `#1F1F1C` ≠ `--ink #1B1D1A`、`#33402A` ≠ `--olive`。
純 SVG 路線的最大紅利就是這個 bug 可以順手修掉（inline SVG 才能被 CSS 變數觸及），**但如果新的 SVG 照樣寫死色票，這條紅利就白拿了**，而且三段火力的主題變數也作用不到角色身上。

**6. 大頭比例與 38% 欄寬的物理衝突沒有被裁決。**
方向 A 的臉高 68%、方向 C 的 68%、方向 B 的 56.6%，在 `1fr 38%` 的右欄裡臉會小到名牌與曬痕全部消失。這條**零測試覆蓋**（全專案唯一的 `gridTemplateColumns` 斷言只驗週報的單欄），改了全綠——**但它是第 9 節規則 2 的成文數字，需要你裁決，不是設計端自己改掉。**

### 一句誠實話

純 SVG 的天花板不是「像不像好看的卡通」，而是**「像不像一個有人格的角色」**。幾何畫得出兇、畫得出圓眼睛、畫得出汗滴，但軍教片班長的核心節拍是**刀子嘴豆腐心**——罵完之後別過頭、不看你、嘴角鬆一下。這個表情是「班長」與「霸凌者」的唯一分界，而它靠的是**克制**，剛好是家族 4 的表演訓練（每格幅度拉滿）最不擅長的。

三個方向都提到要補第五個 mood `soft`。**這一張圖純 SVG 畫得出來（換一組眉＋一組嘴＋瞳孔位移），但畫得出來不等於畫得對。** 它是整個產品裡最需要人類判斷的一張，也是最容易在排程壓力下被砍掉的一張。

## 三條生產路徑

### 路徑 A：全部用 Claude Design 向量

**流程**

1. **半天｜先驗證，再投入。** 請 Claude Design 只產三個純黑剪影（無內部細節、無顏色），縮到 48px 並排。過不了就回頭調帽／髮／肩，不要動下顎。這一關過了，96px 一定過。
2. **半天｜鎖格線。** 產一份 `design/Grid.dc.html`：1024 master 上的眼線 Y、肩線 Y、眼距、臉高、外輪廓線寬、內部線寬、裝飾線下限，三人共用。這份是後面所有東西的憲法。
3. **一天｜阿良 idle 定稿。** 一張，反覆改到滿意。這一張是風格基準，不是交付物。
4. **一天｜零件化。** 要求它把定稿拆成 17–19 個零件並寫成 `avatarSvg(lv, mood)` 的字串產生器，所有顏色走 `var(--...)`。輸出兩個 LOD 變體。
5. **半天｜十二（或十五）張全出，跑四個結構性驗收**（黑剪影、灰階 ΔL*、LOD 隱藏測試、疊圖測試）。這四關在這條路上幾乎不可能失敗——但要真的跑。
6. **兩天｜七畫面 UI 改版 ＋ token 表 ＋ 三階火力變數矩陣。** 改既有的 `design/*.dc.html`，不是重畫。
7. **一天｜回灌 src。** `avatarSvg()` 改寫、`src/styles.css` 的 token 與 `:root[data-level]`、`index.html:7` 的 theme-color、`public/manifest.webmanifest:9-10`、`design/build.mjs:10-11`——**四份手抄調色盤，目前沒有任何同步機制**。改測試裡被硬驗的兩個卡其值與 avatar 的四個字面值。
8. **一天｜上架素材。** KV、App 圖示三張（Default / Dark / Tinted）、啟動畫面、分享卡版型、截圖標語層。
9. **半天｜Playwright 截圖改 1290×2796**（`fullPage: false` ＋ config 加 430×932 @3x project），產五張乾淨底圖，標語疊上。

**時間感**：**七到八個工作天**，一個人＋Claude。其中角色佔三天、UI 佔兩天、回灌與素材佔三天。

**金錢成本**：**接近零**（訂閱內）。真正的成本是你的時間與判斷力。

**品質天花板**：**在家族 4 / 5 / 9 的範圍內，是滿分。** 它產出的東西可以直接跟 Dexter、PPG、Duolingo 那個層級的向量角色放在一起比。**在那個範圍外，是零**——它做不出有筆觸、有質感、有繪畫感的東西，而且勉強做會很難看（十幾層放射狀漸層近似出來的「立體」比乾淨的扁平醜十倍）。

**隱藏成本（三個，都要算進去）**

- **回灌是手工的。** `.dc.html` 內部全是 inline style，`src/styles.css` 是變數與 class，中間沒有自動轉換。`design/build.mjs:10-11` 的 LIGHT/DARK 是 `src/styles.css:6-11` 的逐字複製，改一邊另一邊不會動。這一天是真的一天。
- **`design/build.mjs:82` 對 `avatarSvg()` 的回傳字串做 `s.replace('viewBox="0 0 120 120"', 'viewBox="14 16 92 104"')`。** viewBox 這個字面值與「回傳 string 而非 component」是設計畫布的硬相依，重寫時不能破。
- **文化驗收不在這條路裡。** 五個當過兵的人、96px、2 秒答「哪一國、哪個年代」——這一關要你自己安排，而且路徑 A 因為沒有人類繪師的在地直覺，**這一關的失敗機率比路徑 C 高**。

**什麼情況下這是對的選擇**

- 你選的是方向 A、B、C 任一（三個的骨架都是家族 4，都在能力範圍內）
- 你要的是**可調整的設計系統**，不是十二張定稿圖——因為未來要加表情、要做 96px 版、要換色，向量是唯一能改的
- 你想先上線、先驗證產品，美術之後再升級（`public/officers/` 現在是空的，線上永遠走 SVG 分支，**也就是說這條路的產出今天就能上線**）
- 你的時間比錢多

**什麼情況下這是錯的**
風格方向裡出現「筆觸」「質感」「立體」「手繪感」任一個詞。

### 路徑 B：角色用 AI 算圖（ChatGPT / Firefly），UI 用 Claude Design

**流程**

1. 寫 prompt（§0 風格段 ＋ 三人 ＋ 四 mood，共 12 段）
2. 每張生 10–30 次，人工挑
3. 去背、對齊眼線肩線、統一線寬、補 alpha
4. 轉 512×512 WebP q≥90，放進 `public/officers/{0,1,2}/{mood}.webp`
5. UI 與上架素材走 Claude Design（同路徑 A 的 6–9 步）

**時間感**：**角色三到五天**（其中八成是挑圖與修圖，不是生圖），UI 同路徑 A 的四天。合計**七到九天**，但變異數極大——可能三天搞定，也可能卡在「第七張怎麼生都不像同一個人」。

**金錢成本**：訂閱費（小）。真正成本是挑圖工時。

**品質天花板**：**單張最高，整組最低。**

這條路我不建議，理由是三個結構性問題，不是品質偏好：

**1. 一致性從確定性問題退化成機率問題。** 你會拿到十二張互不相關的點陣圖，每一張的線寬、眼線高度、配件都重新擲骰子。`§4` 驗收表的四項全都變成人工彌補。而且**沒有任何機制保證第十三張（未來加 `soft`）還是同一個人**。

**2. 模型會往美國開，而且它開得很好看。** 生成模型看過的「美國 drill sergeant 卡通」比「中華民國草綠服」多幾個數量級。你會持續拿到 campaign hat（美軍寬邊教官帽）、迷彩、美式肩章、五角星、西方臉——**而且因為它們畫得很好看，你會通過它們**。這是最危險的失敗模式：不是明顯的錯，是舒服的錯。值星帶的左右方向每一張都會隨機翻，當過兵的人一秒看出來。

**3. 資產介面對 raster 有三個坑。**
- `.webp` 副檔名**寫死**在 `src/avatar.tsx:8`，png/jpg/svg 檔不會被撿到
- **全專案沒有任何 `object-fit`**（grep 無結果）。`.officer .av` 是 5.75rem 方框、`.meme .face` 是 `width:100%; aspect-ratio:1`，兩處都 `img{width:100%;height:100%}`。**非正方形的圖會被拉伸變形**，不是裁切也不是留白。走 raster 必須先補 `object-fit: contain`
- raster 分支**完全忽略 `onDark`**。圖檔若烘進底色，會直接蓋在梗圖卡的 olive / red / olive2 上。必須真透明
- 而且 raster 拿不到：跟著 level 變色、跟著深色模式變色、CSS 動態（squash & stretch、眨眼）。**美式卡通的靈魂有一半是時間，raster 一張靜態圖拿不到**

**什麼情況下這是對的選擇**

- 你要的風格**不是向量原生的**（有質感、有筆觸、有立體感），而又請不起繪師——這時候算圖是唯一選項，路徑 A 根本做不了
- 你只需要**一張**圖（主視覺、印刷缺陷疊層、社群素材），不需要十二張一致
- 你願意接受「每次加新表情都要重新擲骰子」這個長期成本

**混用建議**：即使不走路徑 B，**KV 的印刷缺陷疊層（紙纖維、髒污）用一張算圖或素材圖來補是划算的**——它只有一張、不需要一致性、而且正好是 SVG 最不擅長的東西。

### 路徑 C：角色委託繪師，UI 用 Claude Design

**流程**

1. **發包**：把方向書的 §3（造型規則）＋ 不可讓渡清單 ＋ 格線表 ＋ 真實參考照片（草綠服、船形帽、值星帶、名牌——**不要讓繪師或模型發明裝備**）一起交出去
2. **繪師只畫三張 idle 的 turnaround**，人工定稿並鎖定。這是文化判斷留在人手上的那一步
3. **轉向量 master**：依格線重建為純路徑（Claude Design 可以做這一步——把繪師的定稿翻譯成對齊格線的 SVG）
4. **其餘 9–12 張由零件重組**（Claude Design）
5. UI 與上架素材同路徑 A

**時間感**：**繪師一到三週**（外部依賴，不可控），你這邊的 UI 工作可以平行跑。合計**三到四週**，但你自己的工時只有五到六天。

**金錢成本**：**台灣接案繪師的三人角色設計 turnaround，粗估 NT$30,000–90,000 區間——這個數字我沒有把握，實際報價依繪師資歷與授權範圍差很多，請當作量級參考而不是預算。** 加表情變體會另計。

**品質天花板**：**三條裡最高，而且高的地方剛好是另外兩條最弱的地方。**

繪師買到的不是「畫得比較好」，是三樣純技術買不到的東西：

- **文化判斷。** 他會知道 high-and-tight 不對、知道三分頭長什麼樣、知道燙線在哪、知道帽子曬痕的位置。這一項在「哪一國的兵」測試上是決定性的
- **「藏」的那一張。** `soft` 這個 mood 需要的是克制與微妙，是最需要人的一張
- **一個你可以指著說「就這個」的定稿。** 中間路線（方向 B）最大的實務成本就是「無法指著一張參考圖說就這個」，繪師定稿解決這件事

**什麼情況下這是對的選擇**

- 「哪一國的兵」測試是你的硬門檻（方向 B 把這一關當成不可讓渡，方向 A 明說預期會失敗）
- 你打算真的上架、真的推廣，角色是產品的賣點而不是裝飾（第 1 節就寫著「角色是賣點，命令是產品」）
- 你有預算，而且時間可以等
- **三個方向裡，方向 B 最需要這條路**——它主動把一半的方向盤交給一套會自己往美國開的語彙，逐張人工驗收的需求最高

**關鍵：不要讓繪師交十二張圖。** 讓他交三張 turnaround，其餘由 Claude Design 零件化重組。這樣你同時買到繪師的文化判斷與向量的結構一致性，而且成本只有全委託的三分之一。

## 驗收檢查表

### A. 角色資產（六關，前四關結構性、後兩關人工）

1. **黑剪影測試** — 三人填 100% 黑、去掉所有內部細節、縮到 **48px 並排**。分不出來就退回重做。**這一關過了，96px 一定過。這是第一個要跑的，不是最後一個。**
2. **灰階測試** — 全部轉灰階，相鄰色塊 **ΔL\* ≥ 20**。注意：膚色三階（`#EFC9A6` / `#D9A87C` / `#C98F62`）灰階值約 L\*82 / 72 / 63，**只差 9–10，不足**。三人的區隔必須靠帽徽金、值星帶紅、墨鏡黑／帽簷陰影來補，**不能靠膚色**。
3. **LOD 測試** — 隱藏所有 `stroke-width < 24 master 單位` 的元素，角色是否仍成立。老郭的法令紋與白髮線、阿良的汗滴邊緣都在這一關。**汗滴直徑要 ≥ 64**，否則 96px 上只剩 3.7px，會被讀成髒點。
4. **疊圖測試** — 三人 idle 疊在一起降低不透明度，**眼線與肩線必須完全重合**。走向量這關零成本；走算圖這關幾乎必敗。
5. **惡意截圖測試** — 把 `punish` 單張切出來、拿掉所有 app 脈絡、配上最惡意的一句話。**看起來像霸凌梗圖或軍國主義海報就退回重畫。** 這是唯一能抓到公關風險的測試，因為在產品脈絡裡看每張圖都很合理，出事的永遠是脫離脈絡的那一張。
6. **「哪一國的兵」測試** — **5 個真的當過兵的人**，看 96px 縮圖、不給任何說明、2 秒內回答「這是哪一國、哪個年代的兵？」通過條件：**5/5 答「台灣」，≥3/5 答得出 90 年代**。**這一關必須由當過兵的人答，不由你答**——你太熟悉自己的設定，已經沒辦法用陌生的眼睛看它。

**另外三個硬性禁令（不是檢查，是退件條件）**
- **帽徽不得是五角星。** 金／紅五角星是解放軍與蘇聯系統的符號；中華民國是青天白日。改成虛構部隊徽（取十二道放射短芒＋圓框的節奏，明確不是國徽本體）。**現行 `CHARACTER-BRIEF.md §0` 寫的就是錯的，無論走哪條路都要改。**
- **praise 的金色放射線：短線、只在兩側、成對、≤ 4 道、絕不成圓、絕不紅白。** 一旦擴成頭後全圓放射光束就是旭日旗。
- **punish 的嘴角必須向下。** 向上＝獰笑＝施虐。怒吼與獰笑的差別在嘴角方向與眼睛（瞪＝怒，瞇笑＝虐）。
- **任何迷彩即退件。** 草綠服必須純色，一出現迷彩，年代從 1990 跳到現代、題材從軍教片跳到現代戰爭片。

### B. UI（七畫面 ＋ 四條系統相依）

**第 9 節八條規則逐條檢查**（這是既有驗收流程，不因改風而豁免）：
1. 班長永遠在最上面（`.officer` 在畫面頂端）
2. 梗圖卡兩欄、角色 `align-self:end`、**不得絕對定位壓字**
3. 字級 `clamp()` ＋ `overflow-wrap:anywhere`
4. **步驟卡分離：白卡、`▸` 前綴、無梗、無罵**（這一格是「這個 app 的建議是真的」的證據，不娛樂化）
5. 每畫面一顆主動詞按鈕在拇指區、「沒做」為 ghost
6. cmd / log / stand `aspect-ratio:4/5`
7. 高度 <700px 三小鍵橫捲
8. 顏色走 `:root` token 且有 dark 版

**測試不能紅（改了就要同步改測試，不能裝作沒看到）**
- `tests/e2e/system.spec.ts:8` 深色 `--khaki` = `rgb(23,24,19)`、`:15` 淺色 `rgb(227,223,208)` — **唯二被硬驗的色值**
- `tests/e2e/system.spec.ts:71-82` cmd 卡 `height/width ≈ 1.25`（容許 ±0.05）
- `tests/e2e/system.spec.ts:35-36` `overflow-wrap: anywhere` 計算值
- `tests/e2e/system.spec.ts:46-60` 小螢幕 `flexWrap:'nowrap'`、`overflowX:'auto'`、三鍵同一 top

## 建議的動作順序

**不管最後選哪個方向、哪條路徑，前三件事都一樣，總成本不到一天：**

1. **三個純黑剪影，48px 並排。**（半小時）過不了，方向書的造型規則要重談，而不是開始畫十二張。
2. **決定 SVG vs raster 的架構。**（一次對話）這決定你拿到的是「造型」還是「造型 ＋ 節奏」。**它比任何顏色決定都重要**，而且一旦開始畫就很難回頭。
3. **把截圖輸出改成 1290×2796。**（半小時）`tests/shots/` 的 `fullPage: false` ＋ config 加 430×932 @3x project。先產五張乾淨無字的底圖，標語之後疊。

**然後：**

- 若你選的是三個方向中的任一個，**先走路徑 A 到可上線**（角色 SVG ＋ UI ＋ 圖示），把產品推出去
- **KV 可以最後做**——它不擋上架，它擋的是被 Apple 精選和被媒體轉發
- **若「哪一國的兵」測試失敗、而你在意這一關**，再用路徑 C 補三張繪師定稿，重新零件化。既有的向量骨架不會白做——它就是繪師的規格書

**唯一擋在送審前的硬需求是 1024 App 圖示三張**（Default / Dark / Tinted），因為它必須進 binary。這一項 Claude Design 一個下午做得完。
