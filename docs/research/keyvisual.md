## 這一章的三個素材在做三件不同的事

主視覺、App 圖示、App Store 截圖不是同一張圖的三種尺寸，是三種**觀看情境**。混用會三個一起失效。

| 素材 | 實際被看到的樣子 | 注視時間 | 唯一工作 | 失敗的樣子 |
|---|---|---|---|---|
| **App 圖示** | 60×60pt，跟桌面上另外 30 個圖示並排 | 0.3 秒 | 被**認出**、被**找到** | 縮到 60px 糊成一坨草綠 |
| **主視覺 KV** | 大圖（橫幅、社群、媒體轉發、精選提名） | 1–3 秒 | 建立**世界觀與情緒** | 很好看，但看不出這是個 app |
| **App Store 截圖** | 搜尋結果約 215px 寬縮圖 → 點進去全螢幕 | 滑 2–3 張 | 證明「**真的能用**」，展示 loop | 像廣告看板，看不到產品 |

**分工的判準一句話**：圖示賣**識別**，KV 賣**情緒**，截圖賣**可信**。三者共用一個「可以被剪下來單獨用的記號」——金色帽徽——但除此之外不互相複製構圖。

### 主視覺會被貼在哪裡（這決定它的長寬與資訊量）

1. Apple 精選提名（Featuring Nomination）的 artwork
2. 官網 / landing page hero
3. OG image（分享連結預覽，1200×630）
4. IG / Threads 首發與置頂
5. 群組裡被朋友轉發的那一張
6. App Store 截圖第 1 張的**背景層**（不是整張）
7. TestFlight 邀請頁、Product Hunt、媒體邀稿

### KV 放什麼、不放什麼

**放：**
- **一張臉，眼睛落在畫面上 1/3**。人眼先找眼睛，縮到 200px 也還在。
- **一句能當標語的命令**，用 app 內的真實語料。這個 app 的 KV 主角不是 app，是**命令**：`阿財魯肉飯。十二分鐘。` / `不買。七十二小時後再報告。`
- **單一識別色大面積**（草綠或紅滿版）。
- **一個可被剪下單獨用的記號**：金色帽徽。KV 有它、圖示有它、分享卡頁尾有它，三者互相認親。

**不放：**
- 手機外框裡塞一張小小的 UI 截圖——KV 不是截圖的相框。
- 三個以上角色擠一團——社群縮圖必糊。
- 功能條列、箭頭、UI 局部特寫——那是截圖的工作。
- App Store 徽章、Apple logo、星等——精選提名會被退。
- 漸層、光暈、3D——與三個方向共同鎖定的扁平厚描邊直接打架。
- 任何在 200px 寬會消失的細節（名牌上的字、汗滴高光、值星帶金線）。

**一句話定義**：一位班長的臉 + 一道具體到不像廣告的命令 + 滿版識別色。看的人第一個反應應該是「他在兇我」，不是「這個介面好乾淨」。

### 方向差異

三個方向在 KV 上真正的分歧只有一個圖層：**表面處理**。

- **方向 A**：乾淨的厚線平塗，不加做舊層。KV 的力量全押在色彩對比與 burst 形狀上。
- **方向 B**：**加一層九〇年代印刷處理**（套色偏移 1.75%、3% 網點、金色略髒、邊緣褪色）。這層是方向 B 與另外兩者在 KV 上最明顯的分野，也是「莊嚴 → 懷舊」的唯一解藥。
- **方向 C**：整張 KV 改成**塑膠兵吊卡**（泛黃卡紙、吸塑泡殼、頂端打孔掛勾）。年代感押在卡紙上，不押在角色身上。

構圖骨架三個方向共用，見下一節。

## 三位班長的群像構圖

### 先處理特殊關係

六種經典群像構圖各自在說一句話：三角／金字塔＝有領袖的團隊；階梯遞進＝時間與成長；前後景分層＝有親疏遠近的一群人；大小對比＝力量差距；等距並列＝**可選擇的同級選項**；背靠背＝同盟互補。

三位班長**不是隊友，是同一顆旋鈕的三格**。使用者任何時刻只看得到一位（`cycleOfficer` 切換，`level` 存 localStorage，預設 1）。而角色規格已經鎖死：**三人眼線與肩線同高、同一個 slot 互換**。

這個限制是禮物。它代表**等距並列 + 同槽位疊影**是正解：三個完全相同的畫框、相同裁切、相同眼線，差異全部放在「**氣壓**」，不放在「姿勢」。

**明確排除：**
- **三角構圖**——把誰抬高就等於宣告誰是主角，但預設是中檔，會誤導。
- **前後景分層 / 大小對比**——會被讀成「老郭是 boss、阿良是跟班」，變成三個角色的故事，不是三段強度。
- **任何互動姿勢**（勾肩、對視、一起看鏡頭）——暗示他們同時存在於同一個場景，直接摧毀「三選一」的語意。
- **多人整齊列隊、同一姿勢**——一個人是角色，一排一樣的人是集體符號。這條在軍事題材上是硬禁令。
- **仰角英雄鏡位**——宣傳海報文法。全案固定平視或略俯視。

---

### 方案 1：三聯幅明度階梯（**建議主方案**）

**描述**：畫布 1080×1350（4:5，與分享卡同比；另出 1200×630 OG 橫切、1080×1920 IG Story）。三格等寬，格間 16px ink 分隔（漫畫分鏡框，不是留白），最外圈 8px ink 外框。

- **背景明度階梯**：左 `卡其` → 中 `草綠` → 右 `近墨橄欖`。同一張圖裡由亮走到暗＝火力上升，**一個字都不用寫**。
- **表情 `idle` / `bark` / `punish`**，不是三個 idle。讀成「同一個動作被三種人執行」。
- **佔滿度遞增**：三人比例完全一致（眼線肩線鎖死、不放大），但阿良留白多、老郭帽頂被畫框裁掉一點。**壓迫感靠留白被吃掉，不靠尺寸。**
- **紅色全圖只出現兩次**：中格的值星帶、右格的哨繩。兩點連成斜線，把三格串起來並告訴眼睛往右走。
- **底部一條金色刻度線，三個 tick，第 2 個高亮**（對應預設 level 1）。

**理由**：這是唯一同時做到四件事的構圖——不指定主角、不暗示同時在場、把「合照」翻譯成「選擇器」、而且免費繼承槽位契約（三人用同一條格線，對齊是零成本的結構保證，不是要人工對的檢查項）。

**那條刻度線不能省**。沒有它，這張圖會被讀成三個角色的故事；有了它，它是一個旋鈕。

---

### 方案 2：包裝吊卡（**方向 C 的主方案；A/B 可當備用**）

**描述**：同一張卡紙上三個等距泡殼，每個泡殼是白色 15% 不透明圓角矩形 + 一道 45° 硬邊高光斜線。泡殼背板由左到右做明度階梯。卡紙頂端有打孔掛勾，底端同樣是金色三格刻度線。整張疊印刷缺陷（套色偏移、紙纖維）。

**理由**：玩具包裝天然就是「同系列三款」的語法——它一次解決「等距並列」「三人不互動」「可選擇」三件事，而且不需要任何說明文字。打孔掛勾這一個零件同時是識別錨點，也是「這是玩具不是軍隊」的宣告，直接稀釋軍事題材的莊嚴讀感。

**代價**：吊卡語法離 G.I. Joe 吸塑卡只有一步之遙。必須明確走**台灣柑仔店袋裝小兵**的包裝語法（泛黃、套色不準、廉價），不是 Hasbro 的精美吸塑卡。這條線很細，執行時會不斷被拉向錯的那側，因為錯的那側更好看。

---

### 方案 3：一人三面 / 三段曝光（**僅限大 KV，不可用於截圖或社群縮圖**）

**描述**：完全相同的剪影輪廓，三層由淺到深疊在同一個中心點，最上層是老郭，下面兩層向左偏移露出邊緣。

**理由**：語意最準——它字面上就在說「這是同一個人的三段火力」。

**代價**：小尺寸必糊。IG feed 縮圖約 300px、搜尋結果縮圖 215px，疊影在這個尺寸會變成一團髒邊。**只能用在官網 hero 或媒體用大圖，不可當主 KV。**

## App 圖示：不放人物

### 判斷

**不放人物。三個方向都一樣。** 四個理由，依重要性：

1. **圖示不能綁定其中一位班長。** 三位是可切換的同一顆旋鈕，圖示放誰都在說「他是主角」。而預設是中檔黑面，把黑面放上去等於把 lv1 固化成產品臉，lv0 與 lv2 變成附屬。
2. **帽徽是三人的共同記號**，人設文件已經寫明。它是唯一一個「代表全部三人」的視覺物件。
3. **60px 的物理事實。** 胸像在 60px 上只剩一顆頭，而船形帽的輪廓是三人剪影辨識的關鍵——縮到 60px 圓角遮罩一裁，帽子先死。臉就變成一個沒有帽子的黃色圓形。
4. **臉在小圓框裡不耐看**，社群頭像 400×400 也同理：頭像一律用帽徽，不用臉。

**這個判斷不隨方向改變。** 改變的只有帽徽本身的畫法：方向 A 乾淨厚線平塗、方向 B 加套色偏移、方向 C 加硬邊塑膠高光與模具接縫線。

### 一個必須先修的錯

現行角色文件寫的帽徽是「金色五角星在圓框內」——**這是錯的，而且錯得敏感**。中華民國國徽是青天白日（十二道光芒）；**金／紅五角星是解放軍與蘇聯系統的符號**。一個台灣軍教片題材的 app 掛著五角星，在台灣會被截圖轉發。

**解法：做一個虛構部隊徽**——取十二道放射短芒 + 圓框的節奏感，但明確不是國徽本體。這同時避開「在喜劇角色上使用真實國徽」的爭議（刑法有相關條文，**構成要件我不確定，這不是法律意見**；用虛構徽記可以讓這題根本不存在）。

放射短芒的線寬必須 ≥ 畫布 2.3%，否則 60px 上會消失成一圈毛邊。

---

### 方案 甲：帽徽 + 斜向值星帶（沿用現行構圖，建議）

**描述**：正中一枚虛構部隊徽（金 `--gold`，圓環 + 十二道短芒），底色為 level 1 的草綠滿版，左上到右下一道紅色值星帶斜切過去，帶上有細金邊。無文字。

- 帽徽直徑佔畫布 **52%**（不要更小，60px 上會虛）
- 值星帶寬度佔畫布 **14%**，角度 **−38°**
- 邊緣安全區：所有元素離畫布邊 ≥ 10%（iOS 圓角遮罩 + iOS 18 的 tinted/dark 變體都會吃掉外圈）

**理由**：兩個元素、三個顏色、對角線構圖。金 + 紅 + 草綠的組合在桌面上沒有第二個 app 會撞。值星帶的斜線同時解決「圖示太靜態」的問題，而且它是全套裡最不可能被誤讀成美軍的一件配件。

**風險**：紅色斜帶在極小尺寸可能讀成「禁止」符號的斜槓。驗收時務必實測 60px。

---

### 方案 乙：帽徽 + 三格刻度（方向 C 較合，A/B 可選）

**描述**：帽徽置中偏上，下方一條三格刻度線，第 2 格填金。底色用 level 1 的草綠或深墨。

**理由**：它把產品的核心機制（三段火力可選）直接放進圖示。這是唯一一個「圖示本身在說明玩法」的方案，對 App Store 搜尋結果的轉換有實質幫助。

**風險**：刻度線在 60px 上是三個約 4px 的小方塊，會糊成一條。**必須做 LOD**——1024 版有刻度，60/120 版把刻度加粗到跟帽徽同一個線寬階，或直接省略只留帽徽。這代表 iOS 的單張 1024 自動衍生路線不夠用，要手動提供多尺寸。工作量比方案甲高一階。

**我的建議**：**方案甲**。刻度線的說明力在圖示這個尺寸兌現不了，而它多付的代價是真實的。刻度線留給 KV 底部與截圖第 3 張。

## iOS 上架素材完整清單

> **凡標「需查證」的數字，請在送審當天於 App Store Connect 現場確認，不要照抄。** Apple 在 2024–2025 大改過截圖尺寸規則與年齡分級制度，2025 起圖示工具鏈也在換世代。

### A. App 圖示（唯一「沒有就不能送審」的素材）

| 項目 | 規格 | 把握度 |
|---|---|---|
| App Store 圖示 | **1024×1024 PNG**，sRGB 或 Display P3，**不可有 alpha**、**不可自己畫圓角**（系統套遮罩）、不可有透明邊 | 高 |
| 放哪 | Xcode asset catalog 的 `AppIcon`「App Store」槽。**不再單獨上傳到 ASC**，從 binary 讀 | 高 |
| 衍生尺寸 | Xcode 14+ 的「Single Size」：一張 1024 自動衍生全部 iOS 尺寸 | 高 |
| iOS 18+ 變體 | 另備 **Dark** 與 **Tinted** 兩張 1024×1024。Tinted 做成灰階（系統上色），Dark 版要在深色底上仍讀得出 | 中高 |
| iOS 26 / Xcode 26 | 改用 **Icon Composer**（`.icon` 分層檔），變體含 Default / Dark / Clear / Tinted | **需查證**：你的 Xcode 版本是否強制、各 variant 的確切必填欄位 |
| Capacitor | `@capacitor/assets` 由 `assets/icon.png`（1024，不透明）+ `assets/splash.png` 生成整套 | **需查證**你安裝版本的確切檔名慣例 |

**PWA 端現況已經好了**：`public/icons/` 的 180 / 192 / 512 / 512-maskable 四張都無 alpha。唯一要確認的是 maskable 那張的主體在中心 **80% 圓形安全區**內。

**我方的圖示交件清單（方案甲）**：`icon-1024.png`、`icon-1024-dark.png`、`icon-1024-tinted.png`（灰階），加上 PWA 四張、加上 `favicon`。

### B. App Store 截圖

| 項目 | 規格 | 把握度 |
|---|---|---|
| iPhone 必要尺寸 | **6.9" 一組即可**：**1290×2796** 或 **1320×2868**（直式）。其餘尺寸 Apple 自動縮放 | 中高 — **需查證**，這是新規，以 ASC 當天欄位為準 |
| iPad | 只有 target 勾了 iPad 才要。13"：**2064×2752** 或 **2048×2732** | 中 — **需查證** |
| 張數 | 每語系每裝置族**最多 10 張**；最少 1 張 | 上限高把握；**下限需查證** |
| 格式 | PNG 或 JPEG，RGB，**不可有 alpha**（透明會被退） | 高 |
| 搜尋結果露出 | 直式約前 3 張 | 中，會隨 App Store 版面調整 |
| 語系 | 主語系 zh-Hant；未上傳的語系 fallback 到主語系 | 高 |

**現有 `shots/*.png` 不能直接用**：它們是 1170×1992（iPhone 13 @3x），而且 `fullPage: true` 所以高度是內容高不是裝置高（`03-cmd-eat.png` 甚至 2187）。

要改兩處：
- `tests/shots/` 的 `shot()` 加 `fullPage: false`
- `playwright.config.ts` 新增一個專用 project，viewport **430×932 + `deviceScaleFactor: 3`** → 剛好 **1290×2796**

**現有的 `e2e:shots`（iPhone 13 / fullPage）要留著**給第 13.3 節的人工對照用。兩者不要合併——驗收截圖與上架截圖的目的不一樣。

### C. App Preview 影片

- **選配，不是必填。v1 建議先不做，先上架。**
- 每語系每尺寸最多 **3 支**，長度 **15–30 秒**（高把握）
- **必須是 app 實際畫面的錄影**，Apple 明確不接受純動畫廣告片。可加片頭片尾與文字疊層，但主體要是 app 本身（高把握）
- 確切像素 / 編碼 / fps（H.264、.mov/.m4v/.mp4）—— **需查證**，ASC 上傳頁會列當期規格

**之後值得做**：罰則倒數 + 觸覺 + 「雄壯！威武！」是靜態截圖表達不出來的。做的時候只拍一件事：按鍵 → 命令卡出現 → 完成 → 登記。

### D. 啟動畫面

- iOS 不再接受靜態 launch image，必須是 **LaunchScreen.storyboard**（或 Info.plist 的 `UILaunchScreen` 字典）。Capacitor 預設就是 storyboard + Splash image set（高把握）
- `@capacitor/assets` 來源：`splash.png` 與 `splash-dark.png`，**2732×2732**，主體放在中央約 1200×1200 的安全區內（中高，**版本相關，需查證**）

### E. Apple 的內容規定（實際會被退件的點）

| 條款 | 內容 | 對我們的影響 |
|---|---|---|
| **2.3.3** | 截圖必須顯示 **app 使用中**的畫面，不能只有標題藝術圖 / 登入頁 / 啟動畫面 | **第 1 張不能是純 KV**，必須含真實 UI |
| 2.3.3 延伸 | 文字框 / 標語**是允許的**（業界標準）；但畫面部分必須是真實畫面，**不能畫一個不存在的 UI** | 第 3 張「三段火力」必須由三張真實截圖組成，不能重畫 |
| **2.3.10** | 不得出現其他行動平台名稱（Android / Google Play）、價格、未實作的「即將推出」 | 別在截圖寫「即將支援自建情境」 |
| Apple 商標 | 不得放 Apple logo、App Store 徽章、錯誤描繪的 Apple 裝置。要用裝置外框只能用官方 Marketing Guidelines 的產品圖，不可變形裁切 | **需查證**當期允許範圍。**建議直接不用外框** |
| **1.1 / 分級** | 嘲諷式文字內容；`src/banned.ts` 的「罵行為不罵人」護欄是護身符 | Apple 2025 起改用新分級級距（含 13+/16+/18+）。**確切級距與問卷題目需查證**，請在 ASC 現場作答，不要預填 |
| **5.1.1** | `NSLocationWhenInUseUsageDescription` 必須用人話寫用途 | 寫「用來找你附近還開著的店」，不要寫 "for app functionality" |
| 隱私標籤 | 位置 → 用於 App 功能、不連結身分；資料存裝置本機（IndexedDB）要講清楚 | 誠實填 |
| **4.2 最低功能** | 單人、無帳號的小工具容易被以「更像網站」挑戰 | **對策**：一定要有原生才有的東西。觸覺回饋是第一層保險；建議至少再做**罰則倒數的 Live Activity 或本機通知**其中一個 |

**方向 C 的額外風險**：外觀像遊戲但沒有遊戲機制，**可能被要求歸類到 Games**（此條的審核實務**我沒有把握，需查證**）。一旦被歸到 Games，它要跟真遊戲競爭排名，而它會輸。方向 C 的第 3 張截圖也更容易被 2.3.3 挑。

### F. 順手要鎖的 metadata

名稱 ≤30 字元、副標 ≤30、關鍵字欄 100 字元（逗號分隔不含空白）、宣傳文字 170、描述 4000，加上支援 URL、隱私權政策 URL、版權宣告。**字元上限以送審當天 ASC 為準。**

- 名稱：`報告班長 · 決斷連`（manifest 已是這個）
- 副標：`按一顆鍵，班長替你決定。`

## App Store 五張截圖分鏡

### 三條原則

1. **第 1 張在搜尋結果裡只有 215px 寬。** 它只能傳達一件事。
2. **使用者平均滑 2–3 張。** 前 3 張要能獨立賣完整個產品；4–5 張是給已經有興趣的人加碼。
3. **每張一個動詞。** 一張塞兩個賣點 = 零個賣點。

### 共同版型（1290×2796）

```
0 ─────── 620px    標語區（該畫面主色為底）
                   主標 ≤2 行，字級 ~120px，Heavy，行高 1.15
                   副標 ~56px（可省略）
620 ───── 2576px   裝置畫面，裸切、24px 圓角，不用手機外框
2576 ──── 2796px   留白，延伸背景色，不放任何字
```

不用手機外框的理由：外框吃掉約 15% 面積，而我們的 UI 本來就是滿版色塊，裸切更有力，也避開 Apple 裝置圖的合規風險。

**五張並排的色彩節奏**：卡其 → 草綠 → 卡其 → **紅** → 草綠。紅色全篇只出現一次，它就是高潮。

### ① 「按一顆鍵，班長替你決定。」

**畫面**：`01-home` 首頁——黑面 `bark` 表情 + 對話框 + 四塊磁貼。
**要讓瀏覽者理解**：這是什麼、這裡有個人、這東西可以按。
**為什麼第一**：搜尋縮圖必須同時出現「**一張臉**」和「**可以按的東西**」。臉給性格，磁貼給功能。這是唯一同時做到兩件事的畫面。
**注意**：不要用 KV 當第一張——違反 2.3.3，而且縮圖看不出這是個 app。

### ② 「命令長這樣：吃哪家、點什麼、幾分鐘。」

**畫面**：`03-cmd-eat` 草綠命令卡（大字是真實店名「阿財魯肉飯」）+ 下方步驟白卡三行。
**要讓瀏覽者理解**：它不是廢話產生器，它給的是**可執行**的指令。
**要點**：步驟白卡的 `▸` 三行必須完整可讀——那是「具體」的唯一證據。店名用真實可信的，送審用假資料會顯得像 mock。這張也是唯一展示「毒在上卡、情報在下卡」這個結構的機會。

### ③ 「選你今天受得了的火力。」

**畫面**：三格構圖（方案 1 的版型），**但由三張真實截圖組成**——同一張命令卡、三位班長、三種配色，下方金色刻度線、第 2 格高亮。
**要讓瀏覽者理解**：這個 app 有一顆旋鈕，而且別人沒有。
**合規**：這是唯一「合成」的一張，但每一格都是 app 內點頭像可達的真實畫面 → 過 2.3.3。**不可以重畫一個不存在的 UI。**
**為什麼放第 3 位**：前兩張已經讓人懂產品了，第 3 張才有本錢賣「這個別人沒有」。

### ④ 「沒做就罰。倒數不接受討價還價。」

**畫面**：`06-stand` 紅卡大數字倒數。全篇唯一的紅。
**要讓瀏覽者理解**：這件事有代價。沒有賭注的工具 app 不會被記得。
**紅線**：這張是**惡意截圖測試風險最高的一張**。班長的姿態必須是**抱胸、別過頭、等**——不放大、不逼近、不破框、不指向讀者、punish 的嘴角必須向下（向上＝獰笑＝施虐）。壓迫感來自時鐘，不來自身體。**這一張若脫離 app 脈絡、配上最惡意的一句話，看起來像霸凌梗圖，就退回重做。**

### ⑤ 「週日晚上，一張成績單。」

**畫面**：`07-weekly` 週報（服從率數字 hero 化）+ 分享鍵。
**要讓瀏覽者理解**：它會累積，不是一次性玩具；而且它可以分享出去。
**要點**：分享鍵要在畫面裡看得到——它同時預告了病毒傳播路徑。

### 備用第 6 張（若上到 6–7 張）

`04-cmd-buy` 的「**大事不受理。**」紅色 stop 卡。賣的是「它知道自己的邊界」，對 30 歲以上使用者特別有效——證明這不是一個會叫你辭職的 app。

### 標語文案規則

- 全形 **≤14 字一行，最多 2 行**
- **動詞開頭，句號結尾**（跟 app 內文案同一套呼吸）
- 對讀者用命令式，**但不罵讀者**。讀者還不是兵，罵了會流失。罵留在 app 裡
- **不要寫**「AI 驅動」「智慧推薦」「個人化」——SaaS 語言跟軍教片世界觀互斥，一句就把調性毀掉
- 字體與 app 同一套

## 延伸素材

### A. 分享卡（最高優先——app 已內建 `html-to-image` 分享）

使用者會把梗圖卡截圖到 IG / LINE。這是這個產品**最便宜的獲客管道**，而它現在漏了一個洞。

| 素材 | 規格 | 要點 |
|---|---|---|
| 命令卡分享圖 | **1080×1350**（4:5，版面規則已鎖） | **加底部 104px 頁尾**：金色帽徽 + 「決斷連」+ 短網址 |
| IG Story 版 | **1080×1920** | 同一張卡置中，上下各留 250px 給 IG 的 header 與 reply bar |
| 週報成績單 | 1080×1350 | 服從率 % 要大到在 IG feed 縮圖（約 300px）可讀 |
| 罰則截圖 | 1080×1350，紅底 | 自嘲性最強、最容易被轉發的一張 |

**沒有頁尾的分享圖 = 免費傳播但零導流。** 這是最容易犯、也最貴的錯。浮水印規則：右下角金色帽徽，高度約卡片高的 3%，不擋內容。

**LINE 貼圖**是台灣最實際的導流管道，12 張表情正好湊一組。**主圖與貼圖的確切尺寸請查 LINE Creators Market 當期規定，我不確定數字。**

### B. 社群素材

- **OG image 1200×630**（PWA 連結預覽）：KV 的橫式裁切，左字右角色，字要在 600×315 的縮圖仍可讀
- **頭像 400×400**：用**帽徽**，不用臉——臉在小圓框裡會被裁掉船形帽，而帽子是剪影辨識的關鍵
- **貼文模板 1080×1080「今日口令」**：每天一句語料 + 一位班長。`src/officers.ts` 三層各 24 句 = **72 天的零成本日更素材**。這是角色驅動最被低估的紅利

### C. 通知圖

- **iOS 本機通知**用 app 圖示，不需額外圖；但可掛 attachment 圖片（1:1 1024，用 `bark` 表情）
- **若之後上 Android**：需要單色透明的通知圖 **96×96（24dp）**——只有 alpha 通道有效，所以必須是帽徽的純剪影，不能用角色
- **Live Activity / 動態島**（罰則倒數天生適合）：需要 compact leading 圖（帽徽，**單色 template image**）、compact trailing（剩餘秒數）、expanded（頭像 44pt + 大倒數）。這一項做了，4.2 條款的「更像網站」質疑就不成立

### D. 空狀態插畫：**零新資產**

錯誤路徑的文案已經寫好，缺的只是視覺指定。**規則：空狀態 = 頭像 + 一句話 + 一顆按鈕，不畫新場景。**

| 狀態 | 頭像 | 文案（已存在） |
|---|---|---|
| 日記空 | 阿良 `idle` | 「日記是空的。這不是好事。」 |
| 週報未到時間 | 黑面 `idle` | 「週日二十點，再來。」 |
| API 429/5xx | 老郭 `idle` | 「班長在開會。三十秒後再報告。」 |
| 附近 0 家營業 | 黑面 `bark` | 「附近沒有開的。」 |
| 定位被拒 | 黑面 `idle` | 「不報座標？行，班長用常識。」 |

角色驅動 app 的空狀態成本應該趨近於零。

**唯一真的需要新資產的是 Loading / 等待畫面**（`Waiting` 元件）：建議一個 2 幀的帽徽轉動，或 `idle → bark` 兩幀切換。**不要用 spinner**——spinner 是網頁語言，會直接抵銷為了 4.2 條款做的所有原生感努力。

### E. 啟動畫面

- **正解**：卡其滿版（深色模式墨色）+ 中央金色帽徽。就這樣。
- **不要放班長的臉**——臉會讓人以為已經進首頁，然後一秒後臉換成另一個表情，會跳。
- **不要放文字、wordmark、版權宣告、載入動畫**。啟動畫面不是廣告，這是 HIG 的明文。
- `design/Splash.dc.html` 已有工作檔，照這個原則驗收。
- 深色版必備（`splash-dark.png`），與 `index.html` 的 `theme-color`、`manifest.webmanifest` 的 `background_color` 同步。**注意這三處目前是三份互不同步的手抄色值**，改配色時最容易漏。

## 製作順序與關鍵路徑

**照這個順序，不要跳。**

1. **1024 圖示 + Dark + Tinted 三張。** 這是唯一「進不了 binary 就不能送審」的素材，而且它只需要帽徽定稿，不需要角色。順手把五角星改成虛構部隊徽。
2. **改截圖輸出為 1290×2796**（`fullPage: false` + config 加 430×932@3x project），先產 5 張**乾淨無字**的底圖，標語之後疊。半小時的事。
3. **三位班長 12 張表情**（走向量路線就是 `avatarSvg()` 改寫；走資產路線是 `public/officers/{0,1,2}/{idle,bark,praise,punish}.webp`，512×512 透明）。目前 `public/officers/` 是空的——**KV、截圖第 3 張、五個空狀態全部卡在這一項。這是關鍵路徑。**
4. **分享卡頁尾**（104px，帽徽 + 短網址）。工程量極小，但它決定所有自然傳播有沒有導流。
5. **啟動畫面 + PWA maskable 安全區複檢。**
6. **KV。** 它不擋上架，它擋的是被 Apple 精選和被媒體轉發——所以可以最後做，但不能不做。

**兩個必須在角色定稿前跑完的驗收閘門**，成本各半天以內：

- **黑剪影測試**：三人全填 100% 黑、去掉所有內部細節、縮到 48px 並排。分不出來就退回。這關過了，96px 一定過，KV 的三聯幅也一定成立。
- **「哪一國的兵」測試**：5 個當過兵的人，看 96px 縮圖、不給任何說明、2 秒內答「這是哪一國、哪個年代的兵？」。通過條件 5/5 答台灣、≥3/5 答得出 90 年代。**方向 A 預期會失敗這一關**——那不是 bug，是它的定價，但要在發包前知道自己付了這筆錢。
