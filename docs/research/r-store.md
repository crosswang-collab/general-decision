## 1. 主視覺到底在做什麼工作

三種素材是三種「觀看情境」，不是三種尺寸。混用會全部失效：

| 素材 | 被看到的尺寸 | 被看的時間 | 唯一工作 | 失敗長什麼樣 |
|---|---|---|---|---|
| **App 圖示** | 60×60pt（桌面上跟 30 個圖示並排） | 0.3 秒 | 被**認出**、被**找到** | 縮到 60px 糊成一坨草綠 |
| **主視覺 KV** | 大圖（橫幅／社群／媒體轉發） | 1–3 秒 | 建立**世界觀與情緒**，賣「這是什麼感覺」 | 看完很好看，但不知道是個 app |
| **App Store 截圖** | 搜尋結果約 215px 寬縮圖 → 點進去全螢幕 | 滑 2–3 張 | 證明「**真的能用**」、展示 loop | 像廣告看板，看不到產品 |

**主視覺實際會被貼在這七個地方**（這決定它的長寬與資訊量）：

1. Apple 精選提名（App Store Featuring Nomination）的 artwork
2. 官網／landing page hero
3. OG image（分享連結預覽，1200×630）
4. IG／Threads 首發貼文與置頂
5. 朋友在群組轉發的那一張
6. App Store 截圖第 1 張的**背景層**（不是整張）
7. TestFlight 邀請頁、Product Hunt、媒體邀稿

### 角色驅動的 app，KV 該放什麼

**放：**
- **角色的臉，眼睛落在畫面上 1/3**（人眼先找眼睛；縮到 200px 也還在）
- **一句能當標語的命令**，用 app 內真實語料。這個 app 的 KV 主角不是 app，是**命令**。例如：`阿財魯肉飯。十二分鐘。` 或 `不買。七十二小時後再報告。`
- **單一識別色大面積**（草綠 `#4A5733` 或紅 `#B3261E` 滿版）——Headspace 那條原則：一眼認得是誰家的
- **一個可以被剪下來單獨用的記號**：金色帽徽、紅色值星帶。KV 裡有它，圖示裡有它，分享卡頁尾有它 → 三者互相認親

**不放：**
- **手機外框裡塞一張小小的 UI 截圖** — KV 不是截圖的相框，截圖自己會上場
- **三個以上角色擠在一起** — 縮到縮圖就變一坨
- **功能條列、箭頭、UI 局部特寫** — 那是截圖的工作
- **App Store 徽章、Apple logo、星等** — 精選提名會被退
- **漸層、陰影、光暈、3D** — 跟 `CHARACTER-BRIEF.md` 鎖死的 flat thick-outline 直接打架
- **任何在 200px 寬會消失的細節**（名牌上的字、汗滴的高光、值星帶的金線）

**這個 app 的 KV 一句話定義**：一位班長的臉，佔畫面 55–65% 高，旁邊一道具體到不像廣告的命令，背景是滿版草綠。看的人第一個反應應該是「他在兇我」，不是「這個介面好乾淨」。

## 2. 三人群像構圖：經典解法 vs 這個 app 的特例

### 六種經典解法各自在說什麼

| 構圖 | 傳達的關係 | 典型用途 |
|---|---|---|
| **三角／金字塔** | 有領袖的團隊，一主二從 | 主角 + 夥伴（RPG 隊伍海報） |
| **階梯／對角遞進** | 時間、成長、進程 | 角色的過去現在未來 |
| **前後景分層（重疊）** | 同一個世界裡的一群人，有親疏遠近 | 群像劇 |
| **大小對比** | 力量差距、威脅、保護 | 主角 vs 反派 |
| **等距並列（lineup）** | **可選擇的選項、同級、目錄** | 角色選擇畫面 |
| **背靠背** | 同盟、互補、各守一方 | 雙人／三人小隊 |

### 這個 app 的特殊關係

三位班長**不是隊友，是同一顆旋鈕的三格**。使用者任何時刻只看得到一位（`app.tsx` 的 `cycleOfficer`，`level` 存在 localStorage，預設 1）。而 `CHARACTER-BRIEF.md` 已經鎖死：**眼線與肩線三人同高、同一個 slot 互換**。

這個限制是禮物。它代表**等距並列 + 同格疊影**是唯一正解：三個完全相同的畫框、相同裁切、相同眼線，差異全部放在「**氣壓**」而不是「姿勢」。

**具體可以直接畫的參數：**

- 三格等寬，格間距 8–12px（以 1024 寬計）或**無間隙共用一條底線**
- **背景明度階梯**：左 `#E3DFD0` 卡其 → 中 `#4A5733` 草綠 → 右 `#1B1D1A` 墨。同一張圖裡明度由亮走到暗 = 火力上升，一個字都不用寫
- **佔滿度遞增**：三人比例一致（眼線鎖死），但阿良留白多、老郭頂到畫框上緣（帽子被裁掉一點）。壓迫感靠留白，不靠放大
- **表情用 `idle` / `bark` / `punish` 三段**，不是三個都 idle → 讀成「同一個動作被三種人執行」
- **底部一條金色刻度線**，三個 tick，第 2 個高亮（對應 app 預設 level 1）。這條刻度就是把「合照」翻譯成「選擇器」的關鍵零件
- **紅色只出現兩次**：中格黑面的值星帶、右格老郭的哨繩。兩點連成一條斜向動線，把三格串起來，也告訴眼睛「往右走」

**明確要避免的：**

- **三角構圖** — 把誰抬高就等於宣告誰是主角，但預設是中檔，會誤導
- **前後景分層／大小對比** — 會被讀成「老郭是 boss、阿良是跟班」，變成三個角色的故事，不是三段強度
- **任何互動姿勢**（勾肩、對視、一起看鏡頭笑）— 暗示他們同時存在於同一個場景，直接摧毀「三選一」的語意
- **三人擠成一團** — 社群縮圖會糊成一坨草綠

**備案（更凶，但只能用在大 KV）**：一人三面／三段曝光——完全相同的剪影輪廓，三層由淺到深疊在同一個中心點，最上層是老郭。語意最準（「這是同一個人的三段火力」），但小尺寸必糊，不要用在截圖或社群縮圖。

## 3. iOS 上架實際需要的素材與規格

> **我對哪些數字有把握、哪些沒有，下面逐條標示。Apple 在 2024–2025 大改過截圖尺寸規則與分級制度，凡標「需要查證」的請在送審當天於 App Store Connect 現場確認，不要照我寫的填。**

### A. App 圖示（唯一「沒有就不能送審」的素材）

| 項目 | 規格 | 把握度 |
|---|---|---|
| App Store 圖示 | **1024×1024 PNG**，sRGB 或 Display P3，**不可有 alpha**、**不可自己畫圓角**（系統套遮罩）、不可有透明邊 | 高 |
| 放哪裡 | Xcode asset catalog 的 `AppIcon`「App Store」槽。**現在不再單獨上傳到 App Store Connect**，它從 binary 讀 | 高 |
| 衍生尺寸 | Xcode 14+ 用「Single Size」，一張 1024 自動衍生全部 iOS 尺寸 | 高 |
| iOS 18+ 變體 | 另備 **Dark** 與 **Tinted** 兩張 1024×1024。Tinted 做成灰階（系統上色），Dark 版要在系統深色底上還讀得出來 | 中高 |
| iOS 26 / Xcode 26 | 改用 **Icon Composer**（`.icon` 分層檔，Liquid Glass），變體含 Default / Dark / Clear / Tinted | **需要查證**：你的 Xcode 版本是否強制、以及各 variant 的確切必填欄位 |
| Capacitor | `@capacitor/assets` 從 `assets/icon.png`（1024×1024 不透明）+ `assets/splash.png` 生成整套 | **需要查證**你安裝版本的確切檔名慣例（`icon-only` / `icon-foreground` / `icon-background` 這組是給 Android adaptive 的） |

**PWA 端現況：已經好了。** `public/icons/` 的 180 / 192 / 512 / 512-maskable 四張都無 alpha ✅。唯一要確認的是 maskable 那張的主體在中心 **80% 圓形安全區**內。

**圖示設計決定**：現有 prompt（帽徽金星 + 紅值星帶斜線）是對的，**不要放臉**。三位班長可切換，圖示不能綁定其中一位；帽徽是三人**共同**記號（`CHARACTER-BRIEF.md` §1 已經寫明「三人共同」）。

### B. App Store 截圖

| 項目 | 規格 | 把握度 |
|---|---|---|
| iPhone 必要尺寸 | **6.9" 一組即可**：**1290×2796** 或 **1320×2868**（直式）。其餘尺寸 Apple 自動縮放 | 中高 — **需要查證**：這是 2024/2025 的新規，送審當天以 ASC 實際欄位為準 |
| iPad | 只有 target 勾了 iPad 才要。13"：**2064×2752** 或 **2048×2732** | 中 — **需要查證** |
| 張數 | 每語系每裝置族**最多 10 張**；最少 1 張 | 上限高把握；**下限需要查證**（ASC 曾要求過更多） |
| 格式 | PNG 或 JPEG，RGB，**不可有 alpha**（透明會被退） | 高 |
| 搜尋結果露出 | 直式約前 3 張 | 中 — 會隨 App Store 版面調整 |
| 語系 | 主語系 zh-Hant；未上傳的語系 fallback 到主語系 | 高 |

**你現在的 `shots/*.png` 不能直接用**：是 1170×1992（iPhone 13 @3x）、而且 `fullPage: true` 所以高度是內容高不是裝置高（`03-cmd-eat.png` 甚至是 2187）。

要改的是 `/Users/crosswang/Downloads/general-decide/tests/shots/` 裡的 `shot()`：

```ts
await page.screenshot({ path: `${DIR}/${name}.png`, fullPage: false })
```

以及在 `/Users/crosswang/Downloads/general-decide/playwright.config.ts` 加一個專用 project，viewport **430×932 + `deviceScaleFactor: 3`** → 剛好 **1290×2796**。`e2e:shots` 現有那套（iPhone 13 / fullPage）繼續留著給第 13.3 節的人工對照用，兩者不要合併——驗收截圖和上架截圖的目的不一樣。

### C. App Preview 影片

- **選配，不是必填。** v1 建議先不做，先上架。
- 每語系每尺寸最多 **3 支**，長度 **15–30 秒**。（把握度：高）
- **必須是 app 實際畫面的錄影**，Apple 明確不接受純動畫廣告片。可加片頭片尾與文字疊層，但主體要是 app 本身。（高）
- 確切像素／編碼／fps（H.264、.mov/.m4v/.mp4）— **需要查證**，ASC 上傳頁會列當期規格。
- **這個 app 之後值得做**：罰則倒數 + 觸覺 + 「雄壯！威武！」是靜態截圖表達不出來的東西。做的時候只拍一件事：按鍵 → 命令卡出現 → 完成 → 登記。

### D. 啟動畫面

- iOS 不再接受靜態 launch image，必須是 **LaunchScreen.storyboard**（或 Info.plist 的 `UILaunchScreen` 字典）。Capacitor 預設就是 storyboard + Splash image set。（高）
- `@capacitor/assets` 來源：`splash.png` 與 `splash-dark.png`，**2732×2732**，主體放在中央約 1200×1200 的安全區內（各裝置裁切比例不同）。（中高，**版本相關，需要查證**）
- **HIG：啟動畫面不是廣告。**不放文字、不放 wordmark、不放版權宣告、不放載入動畫。
- **這個 app 的正解**：卡其 `#E3DFD0`（深色模式 `#1B1D1A`）滿版 + 中央金色帽徽。**不要放班長的臉**——臉會讓人以為已經進首頁，然後一秒後臉換成另一個表情，會跳。`design/Splash.dc.html` 已經有工作檔，照這個原則驗收。

### E. Apple 對內容的規定（實際會被退件的點）

| 條款 | 內容 | 對你的影響 |
|---|---|---|
| **2.3.3** | 截圖必須顯示 **app 使用中**的畫面，不能只有標題藝術圖／登入頁／啟動畫面 | **第 1 張不能是純 KV**，必須含真實 UI |
| 2.3.3 延伸 | 文字框／標語**是允許的**（業界標準）；但畫面部分必須是真實 app 畫面，**不能畫一個不存在的 UI** | 你的第 3 張「三段火力」必須由三張真實截圖組成，不能重畫 |
| **2.3.10** | 不得出現其他行動平台名稱（Android / Google Play）、價格、未實作的「即將推出」功能 | 別在截圖寫「即將支援自建情境」 |
| Apple 商標 | 不得放 Apple logo、App Store 徽章、錯誤描繪的 Apple 裝置。要用裝置外框只能用 Apple Marketing Guidelines 的官方產品圖，不可變形裁切 | **需要查證**當期 Marketing Guidelines 的允許範圍。建議直接**不用外框** |
| **1.1 / 分級** | 這個 app 是嘲諷式文字。`src/banned.ts` 的「罵行為不罵人」護欄就是你的護身符 | Apple 2025 起改用新分級級距（含 13+/16+/18+）。**確切級距與問卷題目需要查證**，請在 ASC 現場作答，不要預填 |
| **5.1.1 權限** | `NSLocationWhenInUseUsageDescription` 必須用人話寫用途 | 你用 Places（eat / rest）。寫「用來找你附近還開著的店」，不要寫「for app functionality」 |
| 隱私標籤 | 誠實填：位置 → 用於 App 功能、不連結身分；資料存在裝置本機 | IndexedDB 本機儲存要在標籤裡講清楚 |
| **4.2 最低功能** | 單人、無帳號的小工具容易被以「更像網站」挑戰 | **對策**：一定要有原生才有的東西。`DESIGN-BRIEF.md` §5.3 規劃的**觸覺回饋**就是在買這個保險，另外建議至少做**罰則倒數的 Live Activity 或本機通知**其中一個 |

### F. 順手要鎖的 metadata 文字

名稱 ≤30 字元、副標 ≤30、關鍵字欄 100 字元（逗號分隔不含空白）、宣傳文字 170、描述 4000，加上支援 URL、隱私權政策 URL、版權宣告。**字元上限以送審當天 ASC 為準。**

名稱建議：`報告班長 · 決斷連`（manifest 已經是這個）。副標：`按一顆鍵，班長替你決定。`

## 4. 五張截圖的分鏡

### 三條原則

1. **第 1 張在搜尋結果裡只有 215px 寬。**它只能傳達一件事。
2. **使用者平均滑 2–3 張。**前 3 張要能獨立賣完整個產品；4–5 張是給已經有興趣的人加碼。
3. **每張一個動詞。**一張塞兩個賣點 = 零個賣點。

### 共同版型（1290×2796）

```
0 ─────── 620px   標語區（該畫面主色為底）
                  主標 ≤2 行，字級 ~120px，Heavy，行高 1.15
                  副標 ~56px（可省略）
620 ───── 2576px  裝置畫面，裸切、24px 圓角，不用手機外框
                  （外框吃掉 15% 面積；你的 UI 本來就是滿版色塊，裸切更有力）
2576 ──── 2796px  留白，延伸背景色，不放任何字
                  （縮圖會被裁、Home indicator 會壓）
```

**五張並排的色彩節奏**：卡其 → 草綠 → 卡其 → **紅** → 草綠。紅色全篇只出現一次，它就是高潮。

### 分鏡

**① 「按一顆鍵，班長替你決定。」**
畫面：`01-home` 首頁——黑面 `bark` 表情 + 對話框 + 四塊磁貼。
為什麼第一：搜尋縮圖必須同時出現「**一張臉**」和「**可以按的東西**」。臉給性格，磁貼給功能。這是唯一同時做到兩件事的畫面。
注意：**不要用 KV 當第一張**——違反 2.3.3，而且縮圖看不出這是個 app。

**② 「命令長這樣：吃哪家、點什麼、幾分鐘。」**
畫面：`03-cmd-eat` 草綠命令卡（大字＝真實店名「阿財魯肉飯」）+ 下方步驟白卡三行。
這是產品的心臟：證明它不是廢話產生器，它給的是**可執行**的指令。步驟白卡的 `▸` 三行一定要完整可讀——那是「具體」的證據。店名用真實可信的（送審用 lorem 會顯得像 mock）。

**③ 「選你今天受得了的火力。」**
畫面：Q2 那個三格構圖，**但由三張真實截圖組成**——同一張命令卡、三位班長、三種配色，下方金色刻度線、第 2 格高亮。
這是唯一「合成」的一張，但每一格都是 app 內點頭像可達的真實畫面 → 合規。
放第 3 位而不是第 1 位：前兩張已經讓人懂產品了，第 3 張才有本錢賣「這個別人沒有」。

**④ 「沒做就罰。倒數不接受討價還價。」**
畫面：`06-stand` 紅卡大數字倒數。全篇唯一的紅。
作用：建立**賭注**。沒有代價的工具 app 不會被記得。這張也順便展示了 `DESIGN-BRIEF.md` §5.2 要改好的「壓迫感」。

**⑤ 「週日晚上，一張成績單。」**
畫面：`07-weekly` 週報（服從率數字 hero 化）+ 分享鍵。
作用：**留存證明**——不是一次性玩具，它會累積。這張也預告了病毒傳播（有分享鍵）。

**備用第 6 張**（若要上到 6–7 張）：`04-cmd-buy` 的「**大事不受理。**」紅色 stop 卡。賣的是「它知道自己的邊界」，對 30 歲以上使用者特別有效——證明這不是一個會叫你辭職的 app。

### 標語文案規則

- 全形 **≤14 字一行，最多 2 行**
- **動詞開頭，句號結尾**（跟 app 內文案同一套呼吸）
- 對讀者用命令式，**但不罵讀者**。讀者還不是兵，罵了會流失。罵留在 app 裡
- **不要寫**「AI 驅動」「智慧推薦」「個人化」——SaaS 語言跟軍教片世界觀互斥，一句就把調性毀掉
- 字體與 app 同一套（PingFang TC Heavy）

## 5. 上架以外的延伸素材

### A. 分享／病毒（最高優先——app 已經內建 `html-to-image` 分享）

### B. 社群經營

- **OG image 1200×630**（PWA 連結預覽）：KV 的橫式裁切，左字右角色，字要在 600×315 的縮圖仍可讀
- **頭像 400×400**：用**帽徽**，不要用臉——臉在小圓框裡會被裁掉船形帽，而帽子是剪影辨識的關鍵
- **貼文模板 1080×1080「今日口令」**：每天一句語料 + 一位班長。`src/officers.ts` 三層各 24 句 = **72 天的零成本日更素材**，這是角色驅動最被低估的紅利
- **LINE 貼圖**（台灣最實際的導流管道）：12 張表情正好湊一組。**主圖與貼圖的確切尺寸請查 LINE Creators Market 當期規定，我不確定數字**

### C. app 內還缺的狀態插畫（**用現有 12 張，一張新圖都不用畫**）

`DECIDE-DEV-DOC-v1.md` 第 11 節的錯誤路徑已經寫好文案，缺的是視覺指定：

**規則：空狀態 = 頭像 + 一句話 + 一顆按鈕，不畫新場景。**角色驅動 app 的空狀態成本應該趨近於零。

唯一真的需要新資產的是 **Loading／等待畫面**（`Waiting` 元件）：建議一個 2 幀的帽徽轉動，或 `idle → bark` 兩幀切換，**不要用 spinner**——spinner 是網頁語言，會直接抵銷你為了 4.2 條款做的所有原生感努力。

### D. 原生延伸（同時是 4.2 條款的保險）

- **Live Activity / 動態島**：罰則倒數是天生的 Live Activity。需要 compact leading 圖（帽徽，單色 template image）、compact trailing（剩餘秒數）、expanded（頭像 44pt + 大倒數）。這一項做了，「更像網站」的質疑就不成立
- **本機通知**：iOS 通知用 app 圖示，不需額外圖；但可掛 attachment 圖片（1:1 1024，用 `bark` 表情）。**若之後上 Android，需要單色透明的通知圖 96×96（24dp）**
- **Widget**：systemSmall，帽徽 + 一句今日口令，點了直接進首頁
- **App Store 自訂產品頁（Custom Product Pages）**：做「阿良版」（給怕兇的人）和「老郭版」（給重訓／自律社群）兩組截圖，分流投放。免費、被嚴重低估
- **In-App Events**（莒光園地週報）：Apple 的活動卡片有指定尺寸，**需要查證**
